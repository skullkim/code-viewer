# CodeNavigator

맥 네이티브 코드 내비게이터. **Neovim을 임베드해 편집하고, 심볼 인덱스로 정의·참조를 즉시 찾는다.**

여러 프로젝트를 탭으로 동시에 열고, 마크다운·HTML을 편집기 위에 얹어 읽는다.

```
SwiftUI + AppKit · Neovim --embed (MessagePack-RPC) · tree-sitter · macOS 14+
```

## 설계 원칙

- **인덱스는 파생물이다** — 소스에서 전량 재생성할 수 있다.
- **편집은 Neovim을 통해서만 일어난다** — 앱은 키를 표기법으로 바꿔 넘기고, 버퍼는 건드리지 않는다.
- **사용자의 `~/.config/nvim` 설정을 침범하지 않는다.**
- **조용히 비우지 않는다** — 화면이 비면 이유를 말한다. 못 읽은 것과 막은 것과 빈 것은 다른 사건이다.

## 설치

**[최신 릴리스에서 `.dmg` 받기](https://github.com/skullkim/code-viewer/releases/latest)** — 유니버설(`x86_64 arm64`), 5.3MB

1. `.dmg`를 열고 **CodeNavigator.app을 Applications로 드래그**
2. 처음 열 때 **우클릭 → 열기 → 열기**

**필요한 것**: macOS 14+ · `nvim` 0.9.0 이상 (`brew install neovim`)

### ⚠ 처음 열 때 경고가 뜬다

이 앱은 **공증(notarize)되지 않았다.** 유료 Developer ID가 없어서다. 그래서 더블클릭하면 macOS가 막는다 — **우클릭 → 열기**를 한 번 하면 그 뒤로는 그냥 열린다.

그래도 막히면:
```bash
xattr -d com.apple.quarantine /Applications/CodeNavigator.app
```

### 처음 실행하면 권한을 묻는다

프로젝트를 문서·데스크탑·다운로드 폴더에서 열면 macOS가 접근 권한을 묻는다. **여는 프로젝트 폴더 안에서만 읽고 쓴다** — 대화상자에 그 문장이 그대로 나온다.

이 대화상자는 한때 결함으로 오해받았다. 답을 기다리는 동안 앱이 `Neovim이 응답하지 않습니다`로 보고했고, 하루가 nvim을 의심하는 데 갔다. 그래서 지금은 문구가 이유를 말한다.

## 소스에서 빌드하기

```bash
swift build -c release            # 빌드
./scripts/bundle.sh               # .app 조립 (권한 문구 검증 + 번들 매니페스트)
open .build/CodeNavigator.app

./scripts/package-dmg.sh          # 배포용 유니버설 .dmg
```

**필요한 것**: 위에 더해 Swift 6

맨 실행 파일에는 번들 신원이 없어 창이 키 윈도우가 되지 않는다 — 그래서 `.app`으로 감싼다 ([ADR-0105](docs/adr/0105-app-bundle-and-target-split.md)).

## 기능

| | |
|---|---|
| **프로젝트** | 여러 프로젝트를 탭으로 동시 개방 · 전환 시 재인덱싱 없음 · 탭마다 트리·검색·편집 세션이 독립 |
| **탐색** | 정의로 이동 · 참조 목록 · 심볼 퍼지 검색(⌘P) · 전문 텍스트 검색(⇧⌘F) |
| **편집** | Neovim 임베드 · Vim / 표준 모드 토글 · 저장 시 자동 재인덱싱 |
| **읽기** | 마크다운·HTML 렌더(⇧⌘V) — 편집기 위에 얹히므로 커서·undo·미저장 변경이 그대로 남는다 |
| **한글** | 한글 자판에서도 Vim 명령키가 동작한다 (자모를 물리 키로 되돌려 표기 생성) |

### 렌더 샌드박스

렌더된 문서는 **원격 로드와 스크립트 실행을 차단**하고 프로젝트 폴더 안으로 접근을 제한한다. 차단·실패·부재를 **각각 다른 문패로** 말한다 — 못 읽은 파일을 "차단됨"으로 세면 보안 신호가 부풀려지고, 부풀려진 신호는 진짜 차단도 못 믿게 만든다.

## 구조

```
Sources/
  CodeNavigatorContract/   프로토콜과 값 타입 — 앱과 엔진의 유일한 경계
  CodeNavigatorCore/       인덱싱 · 검색 · 파일 감시 · Neovim RPC
  CodeNavigatorAppKit/     SwiftUI 셸 · 키 라우팅 · 렌더 파이프라인
  CodeNavigatorApp/        진입점
docs/adr/                  아키텍처 결정 기록 (왜 그렇게 했는가)
scripts/                   번들 조립 · 뷰 마운트 검사 · 포커스 대칭 검사
_workspace/                요구사항 · 설계 · QA 리포트 · 빌드 판정 기록
```

경계가 프로토콜 하나인 이유, tree-sitter를 쓰는 방식, 키를 누가 소유하는지 — 전부 [`docs/adr/`](docs/adr/)에 있다. **결정만이 아니라 기각한 대안과 그 이유**를 적어 두었다.

## 게이트

```bash
./_workspace/gate.sh
```

테스트 1,407건에 더해 이런 것들을 본다:

- **모든 뷰가 실제로 마운트되는가** — 만들어졌는데 어디에도 안 붙은 뷰를 잡는다
- **모든 포커스 표면이 키보드를 받을 수 있는가** — 열림·닫힘 짝만 보면 "아예 없음"이 정답으로 통과한다
- **입력 소스를 바꾸는 호출이 0건인가** — 앱은 사용자 자판을 바꿔 놓지 않는다
- **검사기 자신이 실제로 잡는가** — 각 검사에 자기 검사가 붙어 있다

마지막 항목이 이 게이트의 핵심이다. **검사가 도는 것과 검사가 잡는 것은 다르다.**

## 알려진 미검증

**한글 조합 중의 이동 키** — 한글을 조합하는 도중 방향키·delete·Enter·Home을 누르면 치던 음절이 지켜지는지. 코드로는 처리했고 테스트도 있지만 **실제 자판으로는 확인하지 못했다.** 합성 입력으로 한글 입력 소스를 신뢰성 있게 적용할 수 없었고, 강제로 바꾸는 방법은 "앱이 사용자 자판을 건드리지 않는다"는 요구를 검증 도구가 깨는 것이라 쓰지 않았다.

```bash
bash _workspace/verify-korean-chords.sh    # 사람 손 ~1분
```

그 외 미검증 항목과 인증 근거는 [`_workspace/BUILD_COMPLETE.md`](_workspace/BUILD_COMPLETE.md)에 있다.

## 어떻게 만들어졌나

가상 개발팀(PM·디자이너·백엔드/프론트엔드 시니어·주니어·QA)이 요구사항 → 설계 → TDD → QA 루프로 만들었다. `_workspace/`에 그 과정이 남아 있다 — 요구사항, 디자인 프로토타입, QA 리포트, 그리고 **틀렸다가 뒤집은 판정들**.

이 빌드에서 가장 많이 반복된 실패는 하나였다:

> **테스트가 초록인데 기능이 죽어 있다.**

여덟 번 나왔고, 그중 셋은 키 라우팅의 같은 한 줄 — "나머지 전부"를 받는 기본 분기 — 로 떨어졌다. 그 분기에 무엇이 오는지 아무도 세지 않았다. 그리고 마지막 두 개는 **사용자가 직접 방향키를 눌러 보고** 찾았다.
