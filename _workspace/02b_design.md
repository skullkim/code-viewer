### 0.2 핵심 설계 결정 3건 (대안 · 근거)

#### D-A. 탭 바는 **통합 툴바 바로 아래**, 창 전폭 32px 스트립
| 대안 | 왜 안 되는가 |
|------|-------------|
| **채택** — 툴바 아래 전폭 스트립 | Xcode·Safari(별도 탭 막대)·Terminal·Finder가 모두 이 배치다. 구조적으로도 옳다: 탭 아래의 **모든 것**(트리·에디터·패널·상태바)이 그 탭 소유이고, 탭 위의 툴바는 창 전역 동작이다. 트래픽 라이트(좌측 78px)와 겹치지 않는다 |
| 타이틀바 안에 탭 (Chrome·Safari 컴팩트) | 타이틀바 48px에 이미 트래픽 라이트 + 창 제목 + 모드 세그먼트 + 툴바 버튼 3개가 있다. 900px 창에서 탭에 남는 폭이 200px 미만이다. 게다가 **창 제목은 활성 파일 이름 + 더티 ●**(02 W-1)인데 그 자리를 탭에 내주면 그 정보가 사라진다 |
| macOS 네이티브 창 탭(NSWindow tabbing) | 탭마다 툴바·상태바가 복제되고 탭 제목이 창 제목(= 파일 이름)이 되어 **프로젝트 이름을 못 보여준다**. 배경 탭의 인덱싱 진행을 탭 안에 그릴 수단도 없다. AC-1("프로젝트당 탭")·AC-2(배경 인덱스 유지)를 모두 어렵게 만든다 |

#### D-B. 소스 ↔ 렌더는 **같은 자리 전환(토글)**, 나란히 보기 아님
| 근거 | 내용 |
|------|------|
| AC 문면 | REQ-013 AC-3이 "원본(소스)과 렌더 보기를 **전환**할 수 있다" |
| 물리적 한계 | 02 §4.3의 에디터 최소 폭은 420px다. 나란히 = 트리 240 + 420 + 420 = 1,080px 이상이 필요한데 **최소 창은 720×480**이다. 나란히를 기본으로 두면 최소 창에서 성립하지 않는다 |
| Neovim 소유권 | 렌더가 **덮기만** 하면 nvim 그리드는 크기가 바뀌지 않는다. 나란히는 파일을 열 때마다 nvim UI를 리사이즈(재-attach·전면 리드로)해야 한다 — INV-3·INV-4를 건드리는 비용이 크다 |
| 스크롤 동기화 | 나란히가 쓸모 있으려면 소스 라인 ↔ 렌더 요소 스크롤 동기화가 필요한데, 어떤 AC도 요구하지 않고 비용이 크다. 동기화 없는 나란히는 오히려 불편하다 |
| 목적 | 이 앱은 코드 내비게이터다. 문서는 **읽으려고** 연다 — 반쪽보다 전폭 렌더가 낫다 |

#### D-C. 렌더 가능한 파일의 **기본 보기는 렌더**, 사용자가 소스로 바꾸면 그 파일에 대해 기억

## 2. 사용자 플로우 (추가)

### F-10: 두 번째 프로젝트 열기 (REQ-012 AC-1·AC-5)
1. ⌘O / 탭 바 `＋` / 파일 ▸ 최근 프로젝트 열기 → 맥 표준 폴더 대화상자(기존 F-1 재사용)
2. 분기
   - **아직 안 열린 프로젝트**: 탭 바 **맨 오른쪽에 새 탭 추가 + 즉시 활성화**. 그 탭의 인덱스 칩 `없음 → 인덱싱 중`. 다른 탭은 아무것도 바뀌지 않는다(INV-5)
   - **이미 열린 프로젝트**(AC-5): 새 탭을 만들지 않고 **기존 탭을 활성화**하고 상태바에 `✓ 이미 열려 있는 프로젝트입니다 — 해당 탭으로 이동했습니다` 2초. *조용히 아무 일도 안 일어난 것처럼 보이면 안 된다*
   - **열기 실패**: 기존 W-2 실패 시트 그대로(경로 없음 / 권한 없음). 탭 목록 불변
3. 탭이 0개→1개가 되는 순간 웰컴 화면(W-2)이 3영역으로 바뀌고 **탭 바가 나타난다**

### F-11: 탭 전환 (REQ-012 AC-2)
1. 탭 클릭 / `⇧⌘]`·`⇧⌘[` / `⌘1`~`⌘9` / 넘침 메뉴에서 선택
2. **재인덱싱 없이 즉시** 트리·에디터·패널·검색 결과·상태바가 그 탭 것으로 교체된다. 인덱스는 메모리에 있으므로 대기 표시가 없다
3. 전환 대상 탭이 아직 인덱싱 중이면 그 탭의 상태 그대로 보인다(진행률 칩) — 전환 자체는 기다리지 않는다
4. 활성 탭은 항상 보이도록 탭 바가 자동 스크롤된다

### F-12: 탭 닫기 (REQ-012 AC-3)
1. 탭 `✕` / `⌘W` / 탭 우클릭 ▸ 닫기
2. 분기
   - **더티 버퍼 없음**: 즉시 닫힌다. 그 탭의 인덱스·편집 세션 자원이 정리된다(AC-3)
   - **더티 버퍼 있음**: **W-13 확인 시트**. `저장 후 닫기`(기본) / `저장하지 않고 닫기` / `취소`
3. 닫힌 뒤 활성 탭 = **오른쪽 탭**, 없으면 왼쪽 탭. 마지막 탭이면 **웰컴 화면(W-2)** 으로 돌아가고 탭 바가 사라진다

### F-13: 재시작 복원 (REQ-012 AC-4·AC-6)
1. 앱 시작 → 저장된 탭 목록(순서 포함)과 활성 탭 인덱스를 읽는다
2. 경로 검증 → 열 수 있는 것만 탭으로 만든다
3. **활성 탭부터 인덱싱**하고 나머지는 배경에서 순차 인덱싱(진행률은 각 탭의 스피너)
4. 열 수 없는 것이 1건 이상이면 **W-12 시트 1장으로 묶어** 알린 뒤 목록에서 제거(AC-6). *탭마다 시트를 띄우지 않는다*
5. 복원 결과 탭이 0개면 웰컴 화면(W-2)

### F-14: 문서 렌더 보기 (REQ-013 AC-1·2·3·4·5)
1. 트리/⌘P/⇧⌘F 결과에서 `.md`·`.html` 열기 → **렌더 보기로 열린다**(D-C). 3중 표시: 툴바 `렌더` 버튼 눌림 + 렌더 헤더 바 + 상태바 `[읽기 전용] 렌더 보기`
2. `⇧⌘V` / 헤더의 `[소스 보기]` / 툴바 버튼 → 소스 보기(Neovim). 이 선택은 그 파일에 대해 세션 동안 기억된다
3. 소스에서 편집·저장(F-7) → 렌더 캐시 무효화 → 렌더로 돌아가면 최신 내용. 렌더 보기가 켜진 채 저장되면 **즉시 재렌더하되 스크롤 위치를 유지한다**(AC-5)
4. 렌더 불가 파일에서 `⇧⌘V`: 상태바 `✕ 이 파일은 렌더할 수 없습니다 (.md · .html 만 지원)` 3초. 툴바 버튼은 애초에 **비활성**
5. 렌더 보기 중에도 ⌘P·⇧⌘F는 그대로 동작한다. 결과를 선택하면 **소스 보기로 전환하며 그 라인으로 이동**한다 — 라인 번호는 소스에만 있는 개념이기 때문이다

### F-15: 차단된 리소스 확인 (INV-6)
1. 렌더 헤더에 **상시** `🛡 샌드박스` 칩. 차단된 항목이 있으면 `🛡 차단됨 {n}`으로 개수가 붙는다
2. 칩 클릭/Enter → **W-15 팝오버**: 종류별 개수 + 호스트/경로 + 정책 문구
3. 본문의 이미지 자리는 비우지 않고 **플레이스홀더 박스**로 그린다(호스트·alt 표시)
4. 차단 해제 UI는 **없다.** 팝오버가 우회 경로를 정직하게 알려 준다("원본 그대로 보려면 브라우저에서 파일을 여세요")

**배치·치수**
- 통합 툴바(48px) 바로 아래, 창 전폭, **높이 32px**. 배경 `bg-window`, 아래 `1px border`
- 탭 폭: **최소 112px · 최대 220px**, 남는 폭을 균등 분배. 112px 밑으로는 줄이지 않고 넘침 처리
- 탭이 적어 220px 상한에 걸리면 오른쪽에 빈 자리가 남는다 — 그 자리는 **창 드래그 영역**으로 쓴다(맥 앱 관례). `＋`는 탭 개수와 무관하게 **트레일링 끝에 고정**한다(탭이 늘 때마다 버튼이 움직이면 근육 기억이 깨진다)
- 탭 내부: 좌우 패딩 10px, 요소 간격 6px. `[상태 글리프] [라벨] [더티 ● / 닫기 ✕]`
- 우측 고정 컨트롤: `≫ {n}`(넘침, 조건부) · `＋`(프로젝트 열기 ⌘O). 각 28×28

**탭 하나의 구성 — 무엇을 넣고 무엇을 뺐는가**
| 요소 | 채택 | 근거 / 뺀 이유 |
|------|------|---------------|
| 프로젝트 이름 | ✅ 12.5px, 활성 600 / 비활성 500 | AC-1의 탭 정체성. **11px대는 비-Retina에서 뭉개진다**(이 빌드 실측) — 그래서 12.5px |
| 닫기 `✕` | ✅ 히트 영역 22×22, 글리프 11px | AC-3. 마우스 경로 |
| 인덱싱 진행 글리프 | ✅ **10px** 스피너, 라벨 **왼쪽** | 배경 탭의 인덱싱은 **상태바에 보이지 않는다**(상태바는 활성 탭 것). 탭이 유일한 표면 |
| 더티 ● | ✅ 7px `warning-solid`(기존 dirty-dot 재사용), 라벨 **오른쪽** | 배경 탭의 저장 안 된 변경은 다른 어디에도 안 보인다. 이게 없으면 F-12가 사고가 된다 |
| 인덱싱 **진행률 숫자**(`1,284/4,812`) | ❌ 툴팁으로만 | 탭 안에서는 10px대가 되어 비-Retina에서 못 읽는다. 정확한 수치는 상태바 칩·W-10 팝오버가 이미 소유한다 |
| 프로젝트 아이콘·색 라벨 | ❌ | 어떤 REQ도 요구하지 않는다(스코프 크리프) |
| 파일 경로 전체 | ❌ 툴팁으로만 | 폭 낭비 |
| 편집 세션 상태 | ❌ | 앱 전역 상태다(§1.1). 탭에 두면 미결 ADR에 UI가 종속된다 |

- **더티 ●와 닫기 ✕는 같은 슬롯(22×22)** 을 쓴다: 비활성 탭은 평소 ●(더티가 아니면 빈 슬롯), hover/포커스 시 ✕(VS Code·Safari 관례). **활성 탭은 ✕를 상시 노출**한다(더티면 ●, hover 시 ✕) — 가장 자주 닫는 대상이고 Safari도 그렇게 한다. **키보드 경로(⌘W)가 항상 있으므로 hover 의존이 유일 경로가 아니다**
- **라벨 말줄임은 가운데**(`code-nav…-mac`). 레포 이름은 접두사를 공유하는 경우가 흔해서(`code-navigator-mac` / `code-navigator-web`) 뒤를 자르면 두 탭이 같아 보인다. SwiftUI `.truncationMode(.middle)`
- **동명 프로젝트 구분**: 폴더 이름이 겹칠 때만 상위 1단계를 보조 라벨로 붙인다 — `app · frontend` / `app · backend`(보조는 `text-2`). 겹치지 않으면 붙이지 않는다

**모든 상태**
| 상태 | 표시 | 사용자 행동 |
|------|------|-----------|
| **탭 0개** | 탭 바 **자체가 없다**. 웰컴 화면(W-2) | ⌘O / 최근 목록 |
| **탭 1개** | 탭 바 표시(AC-1 문면 준수 — §10-1에 판정 요청) | ＋로 두 번째 열기 |
| **여러 개** | 균등 분배, 활성 1개 | 클릭·⇧⌘[ ⇧⌘] ·⌘1~9 |
| **활성** | `bg-content` 채움 + `text-1` **600** + 상단 2px `accent` 라인. `aria-selected="true"` | — |
| **비활성** | 투명(`bg-window`) + `text-2` **500** + 탭 사이 1px 세로 hairline | 클릭 |
| **비활성 hover** | `bg-hover` + 닫기 ✕ 노출 | — |
| **인덱싱 중** | 라벨 앞 10px 스피너. 툴팁 `인덱싱 중 1,284/4,812` | 그대로 전환 가능(대기 없음) |
| **전체 재스캔 중** | 같은 스피너(툴팁만 `전체 재스캔 중 …`) | — |
| **인덱스 최신** | 글리프 없음(조용함이 정상) | — |
| **더티 버퍼 있음** | 라벨 뒤 ● `warning-solid`, 툴팁 `저장하지 않은 변경 {n}건` | ⌘W → W-13 |
| **넘침** | 탭이 112px×개수 > 가용 폭이면 탭 바가 가로 스크롤되고 우측에 `≫ {숨은 개수}` 버튼. 클릭 시 **전체 프로젝트 메뉴**(활성에 체크, 인덱싱 중이면 스피너, 더티면 ●). 활성 탭은 항상 자동 스크롤로 보이게 한다 | 메뉴로 어떤 탭이든 도달 — **가로 스크롤 제스처 없이도 전부 접근 가능**(접근성) |
| **드래그 재정렬 중** | 잡힌 탭이 `shadow-pop`으로 떠오르고 나머지가 자리를 비켜 준다. 드롭 위치에 2px `accent` 삽입 표시 | 순서는 즉시 저장되어 재시작에 복원(AC-4) |

**접근성**
- `role="tablist"` / 각 탭 `role="tab"` + `aria-selected` + `aria-controls`, 닫기 버튼에 라벨 `'{프로젝트}' 탭 닫기`
- 탭 바 진입 후 ←→ 이동, Enter/Space 활성화, ⌫/Delete 닫기 — 마우스 없이 완결
- 활성 구분은 **색 단독이 아니다**: 표면(채움) + 굵기(600 vs 500) + accent 라인 + `aria-selected` 4중
- "동작 줄이기"에서 스피너 회전 → 정지 아이콘(02 §4.5 규칙 계승)

**데이터 요구**: §7

### W-12 탭 복원 · 복원 실패 시트 (REQ-012 AC-4·AC-6)

- **컴포넌트**: (복원은 화면이 아니라 시작 동작) + 실패 시 시트 1장 — 글리프 ⚠️, 제목, 사유별 목록, `[확인]`
- **문구**
  - 제목: `일부 프로젝트를 복원하지 못했습니다`
  - 본문: `다음 {n}개 프로젝트는 열 수 없어 탭 목록에서 제거했습니다.`
  - 항목(W-2의 실패 사유 분류를 그대로 재사용 — 문구도 재사용): `{이름} — 경로를 찾을 수 없습니다: {경로}` / `{이름} — 폴더에 접근할 권한이 없습니다: {경로}`
  - 버튼: `확인`
- **모든 상태**
  | 상태 | 표시 |
  |------|------|
  | 저장된 탭 없음(최초 실행) | 웰컴 화면(W-2). 시트 없음 |
  | 전부 복원 성공 | 시트 없음. 활성 탭이 즉시 사용 가능, 나머지는 배경 인덱싱 스피너 |
  | 일부 실패 | 성공한 탭은 정상 복원 + **시트 1장에 실패 목록을 묶어** 표시 |
  | 전부 실패 | 웰컴 화면 + 같은 시트. 최근 프로젝트 목록에서도 해당 항목 제거 |
  | 복원 직후(인덱싱 진행) | 활성 탭 = 상태바 진행률 칩(W-10), 배경 탭 = 탭 스피너. **활성 탭을 먼저 인덱싱한다** |
- **왜 시트 1장인가**: 탭 5개가 사라졌을 때 시트 5장은 학습된 무시(그냥 확인 연타)를 부른다. 한 장에 모으면 실제로 읽힌다
- **접근성**: `role="alertdialog"`, 포커스는 `[확인]`, Esc = 확인, 목록은 `role="list"`

### W-13 탭 닫기 확인 시트 (REQ-012 AC-3, REQ-004 AC-4)

- **언제**: 더티 버퍼가 있는 탭을 닫을 때 **만**. 클린한 탭은 확인 없이 즉시 닫힌다(마찰 최소)
- **컴포넌트**: 시트 — 제목, 파일 목록(최대 5건 + `외 {n}건`), 버튼 3개
- **문구**
  - 제목: `'{프로젝트}' 탭에 저장하지 않은 변경이 있습니다`
  - 본문: `저장하지 않고 닫으면 다음 파일의 변경 사항이 사라집니다.`
  - 버튼: `취소`(Esc) · `저장하지 않고 닫기` · **`저장 후 닫기`(기본, Enter)**
- **INV-3 유지**: `저장 후 닫기`는 앱이 파일을 쓰는 게 아니라 **Neovim에 저장을 요청**하고 완료를 기다린 뒤 닫는다. 저장이 실패하면(권한 등) 닫지 않고 시트를 유지하며, 실패 표시는 Neovim이 자기 영역에 하는 것을 그대로 둔다(02 F-7 규칙 계승)
- **모든 상태**
  | 상태 | 표시 |
  |------|------|
  | 더티 1건 | 파일 1줄 |
  | 더티 여러 건 | 최대 5줄 + `외 {n}건` |
  | 저장 중 | `저장 후 닫기` 비활성 + 스피너, 다른 버튼도 비활성 |
  | 저장 실패 | 시트 유지 + `⚠ 일부 파일을 저장하지 못했습니다 — 소스 보기에서 확인하세요` |
  | 앱 종료 시 더티 탭 여럿 | **탭별로 순차 확인**하지 않고 시트 1장에 `{프로젝트} — {파일 수}건` 으로 묶어 표시. 버튼 동일 |
- **왜 REQ에 없는데 넣는가** (리더 판정 §12-2로 확정)
  1. AC-3의 "정리된다"를 **데이터 손실 없이** 읽었다. REQ-004 AC-4(더티 표시)가 존재하는 이유가 바로 이 순간이다
  2. **Neovim 자신이 수정된 버퍼를 그냥 버리지 않는다**(`E37: No write since last change`). 시트가 없으면 **앱과 편집기가 서로 다른 약속을 하게 된다** — INV-3("편집은 Neovim 을 통해서만")을 지키면서 앱만 더 관대해지는 것은 앞뒤가 안 맞는다
  3. 이 빌드에서 닫은 결함 두 건(⌘S 가 저장되지 않던 것, `gv` 로 엉뚱한 범위가 지워지던 것)이 **정확히 같은 형태**였다 — 조용한 데이터 유실

### W-14 렌더 보기 표면 (REQ-013)

**구조** — 에디터 영역 위에 얹는 별도 표면. **Neovim 그리드는 크기가 바뀌지 않고 가려질 뿐이다.**
```
에디터 영역
├─ 렌더 헤더 바 (28px, bg-window, 하단 1px border)
│   [파일명]  [읽기 전용]  [🛡 샌드박스 | 🛡 차단됨 n]        [소스 보기 ⇧⌘V]
└─ 문서 본문 (bg-content, 세로 스크롤, 본문 최대 폭 720px 중앙 정렬)
```

**"어느 쪽을 보고 있는가"를 드러내는 3중 표시 (AC-3)**
1. 툴바 `[렌더 ⇧⌘V]` 토글 버튼이 **채워짐**(accent) + `aria-pressed="true"`
2. **렌더 헤더 바**의 존재 자체 + `읽기 전용` 배지 + `[소스 보기]` 버튼
3. 상태바 좌측 모드 세그먼트가 **`[읽기 전용] 렌더 보기`** 로 바뀐다 (C-6)

> 3번이 중요한 이유: 렌더 보기 동안 에디터로 가는 키 입력은 전달되지 않는다(W-8 오버레이와 같은 규칙). 그런데 모드 세그먼트가 `NORMAL Vim`을 계속 보여주면 **거짓말**이 된다. REQ-010 AC-3의 취지는 "지금 내 키가 어떻게 해석되는지 항상 안다"이고, 기존 `[편집 불가] 세션 끊김` 칩이 이미 같은 패턴이다. 소스로 돌아가면 직전 모드로 복귀한다.

**읽기 전용이 자연스럽게 읽히게 (AC-4)**
- 본문에 커서·캐럿·선택 캐럿이 없다(텍스트 선택·복사는 가능 — 읽기의 일부다)
- `읽기 전용` 배지가 헤더에 상주하고, 상태바 모드 칩이 `읽기 전용`이다
- 문서 표면에 타이핑하면 **아무 일도 일어나지 않는 대신** 상태바에 `편집은 소스 보기에서 가능합니다 (⇧⌘V)` 2초 — 조용한 무반응은 고장으로 읽힌다
- 본문 폰트가 코드 그리드와 확연히 다르다(산문 14px/1.7 vs 코드 13px/1.6 모노)

**모든 상태**
| 상태 | 표시 | 사용자 행동 |
|------|------|-----------|
| **렌더 중(최초)** | 200ms 넘을 때만 중앙 스피너 + `문서를 렌더하는 중…`. 그 전엔 아무것도 그리지 않는다(깜빡임 방지 — 02 W-3 규칙 계승) | 대기 / ⇧⌘V |
| **재렌더(저장 후)** | **이전 렌더를 그대로 두고** 헤더에만 스피너. 스크롤 위치 유지 (AC-5) | 계속 읽기 |
| **정상(마크다운)** | 헤딩·문단·목록·표·인용·코드블록·구분선·링크·로컬 이미지 | 스크롤·링크·선택 복사 |
| **정상(HTML)** | 같은 표면에 렌더. 스크립트·원격 리소스는 차단(W-15) | 동일 |
| **빈 파일** | 카드: `빈 문서입니다` / `이 파일에는 내용이 없습니다.` + `[소스 보기 ⇧⌘V]` | 소스로 |
| **읽기 실패** | 카드 ⚠️ `문서를 읽을 수 없습니다` / `{사유}` + `[소스 보기]` `[다시 시도]` | 재시도 |
| **인코딩 해석 불가** | 카드 ⚠️ `이 파일의 문자 인코딩을 해석할 수 없습니다` / `UTF-8 텍스트가 아닙니다.` + `[소스 보기]` | 소스로 |
| **크기 상한 초과** | 카드 ⚠️ `문서가 너무 큽니다` / `렌더 상한은 2MB입니다 (이 파일 5.4MB).` + `[소스 보기]` — **앞부분만 잘라서 보여주지 않는다.** 부분 렌더는 "문서가 여기서 끝났다"로 읽히고, 그건 조용한 거짓말이다. 자를 바에는 못 그린다고 말하고 소스로 보낸다 | 소스로 |
| **아주 긴 문서** | 렌더는 하되 **스크롤 위치를 파일별로 기억**한다. 목차·미니맵은 넣지 않는다(REQ 없음) | 스크롤 |
| **깨진 마크업** | 마크다운(CommonMark)·HTML은 관대한 파서다 — 대부분 "실패"가 아니라 **부분 렌더**된다. 위 3종 외의 실패는 정의하지 않는다. AC-6("빈 화면을 보여주지 않는다")은 위 카드 4종 + 빈 파일 카드로 충족한다 | — |
| **렌더 불가 파일에서 토글** | 툴바 버튼 비활성 + ⇧⌘V 시 상태바 `✕ 이 파일은 렌더할 수 없습니다 (.md · .html 만 지원)` 3초 | — |
| **탭 전환 후 복귀** | 렌더/소스 선택은 탭×파일별로 유지 | — |

**링크 동작**
| 링크 | 동작 |
|------|------|
| `#앵커` | 문서 안 스크롤 |
| 프로젝트 루트 안 상대 경로(`./OTHER.md`, `src/a.ts`) | **그 파일을 이 탭에서 연다**(트리 클릭과 같다). 렌더 가능하면 렌더로, 아니면 소스로 |
| 루트 밖 로컬 경로 | 열지 않고 상태바 `✕ 프로젝트 폴더 밖의 파일은 열 수 없습니다` 3초 (INV-6) |
| `http(s)://` | **기본 브라우저**로 연다 + 상태바 `✓ 기본 브라우저에서 열었습니다` 2초. 앱 안에서는 원격 콘텐츠를 절대 그리지 않는다(INV-6) |
| hover 시 | 상태바 중앙에 대상 URL/경로 표시(브라우저 관례) |

**렌더 보기에 코드 내비게이션을 넣지 않는 근거** (01b 설계 메모가 근거를 요구함)
1. `.md`·`.html`은 인덱싱 대상 언어가 아니다(01b 명시) → 렌더 표면 위에 정의로 갈 심볼이 **존재하지 않는다**
2. ⌘B/⇧⌘B를 살려 두면 `✕ 정의를 찾을 수 없습니다`만 반복 출력하는 죽은 경로가 된다
3. 대신 **프로젝트 전역 검색(⌘P·⇧⌘F)은 렌더 보기에서도 그대로 살아 있다** — 문서를 읽다가 코드로 건너가는 실제 동선은 이쪽이다(F-14-5)
→ **결정**: 렌더 보기에서 ⌘B·⇧⌘B는 비활성(메뉴에서도 흐림), ⌘P·⇧⌘F는 활성

**접근성**
- 문서 표면 `role="document"`, 진입 시 포커스, ↑↓·PageUp/Down·Home/End 스크롤
- 헤딩 계층을 그대로 마크업(스크린리더 랜드마크 탐색)
- 이미지 alt를 보존한다. 차단된 이미지는 `차단된 원격 이미지: {alt}`로 읽힌다(W-15)
- 링크는 텍스트로 구분 가능해야 한다 — 색(`accent-text`)만이 아니라 **밑줄**을 함께 쓴다(색 단독 금지 규칙)
- 코드블록은 가로 스크롤 컨테이너 — 문서 전체가 가로로 밀리지 않는다

### W-15 차단 리소스 고지 (INV-6)

> **설계 원칙**: 차단은 기본값이고 협상 대상이 아니다. 그러나 **차단을 조용히 하면 "왜 이미지가 안 보이지"가 되고, 사용자는 앱이 고장 났다고 판단한다.** 그래서 차단은 *보이게* 한다.

**세 층위**
| 층위 | 무엇 | 왜 |
|------|------|-----|
| ① 헤더 칩(상시) | `🛡 샌드박스` — 차단 0건일 때도 표시 | "이 문서는 원본과 다르게 보일 수 있다"는 상시 고지. W-5 근사 안내 배너와 같은 태도 |
| ② 헤더 칩(카운트) | `🛡 차단됨 {n}` — 1건 이상일 때 | 무엇이 빠졌는지 셀 수 있게 |
| ③ 본문 플레이스홀더 | 이미지가 있어야 할 자리에 박스 | 자리를 비우면 레이아웃도 깨지고 이유도 안 보인다 |

**본문 플레이스홀더**
- 파선 1px `border-strong`, 배경 `bg-sidebar`, 글자 `text-2` 12.5px, 아이콘 🛡
- 원본에 width/height가 있으면 그 비율, 없으면 높이 88px
- 3줄: `🛡 원격 이미지가 차단되었습니다` / `{호스트}` (예: `raw.githubusercontent.com`) / `alt: {대체 텍스트}` (alt 없으면 이 줄 생략)
- 루트 밖 로컬 이미지: `🛡 프로젝트 폴더 밖의 파일은 표시하지 않습니다` / `{원본 경로}`
- **색은 danger가 아니라 중립(text-2)** — 차단은 오류가 아니라 보호다. danger는 실제 실패에만 쓴다

**허용되는 것 (중요)**
- **프로젝트 루트 안의 로컬 이미지는 정상 표시한다.** INV-6은 "로컬 파일 접근을 열린 프로젝트 루트 안으로 제한"이지 금지가 아니다. README 이미지 대부분이 여기 해당한다
- 탭이 여럿이면 "열린 프로젝트 루트" = **그 탭의 루트**로 좁힌다(INV-5와 정합 — A 탭 문서가 B 탭 파일을 읽으면 격리 위반이다)

**팝오버(칩 클릭)**
```
이 문서에서 차단된 항목
  원격 이미지        2   raw.githubusercontent.com
  스크립트           1   (인라인)
  원격 스타일시트     1   cdn.jsdelivr.net
  프로젝트 밖 파일    1   ../../.ssh/config
────────────────────────────────────────────
렌더 보기는 네트워크 요청을 하지 않고 스크립트를 실행하지 않습니다.
이 차단은 해제할 수 없습니다 — 원본 그대로 보려면 브라우저에서 파일을 여세요.
```
- 종류: **원격 이미지 · 스크립트 · 원격 스타일시트 · 원격 폰트 · 프레임(iframe/object/embed) · 프로젝트 밖 파일** 6종
- 스크립트·스타일시트·폰트에는 본문 플레이스홀더를 그리지 않는다 — 원래 보이지 않는 요소라 자리 표시가 노이즈다. 이 층위는 팝오버가 담당한다
- **차단 해제 버튼은 없다.** INV-6의 "완화는 사용자가 명시적으로 요청할 때만"은 *미래의 요구사항*이지 화면의 토글이 아니다
- 마크다운 안에 박힌 HTML도 같은 규칙을 받는다(INV-6 명시)

**모든 상태**
| 상태 | 표시 |
|------|------|
| 차단 0건 | 칩 `🛡 샌드박스`(중립), 팝오버 내용 = `차단된 항목이 없습니다` + 정책 문구 |
| 차단 있음 | 칩 `🛡 차단됨 {n}` + 본문 플레이스홀더 |
| 차단 아주 많음(예: 40건) | 칩 `🛡 차단됨 40`, 팝오버는 종류별로 **집계**해 6줄 이내. 호스트가 여럿이면 `{호스트} 외 {n}곳` |
| HTML 문서 전체가 스크립트 의존 | 렌더는 되지만 비어 보일 수 있다 → 본문 상단에 배너 `이 페이지는 스크립트로 내용을 그립니다 — 렌더 보기에서는 스크립트가 실행되지 않습니다` |

**접근성**: 칩은 버튼(`aria-haspopup`), 팝오버는 `role="dialog"` + Esc 닫기, 플레이스홀더는 `role="img"` + `aria-label="차단된 원격 이미지: {alt}"`

### 5.3 창 크기 적응 (02 §4.4에 행 추가)
| 창 폭 | 탭 바 |
|-------|------|
| 임의 | 탭 폭 = 남는 폭 균등 분배, **112px ≤ 폭 ≤ 220px** |
| 탭이 가용 폭을 넘음 | 가로 스크롤 + `≫ {n}` 넘침 메뉴. 활성 탭은 항상 스크롤되어 보인다 |
| <900px | 렌더 본문 최대 폭 = `min(720px, 가용 폭 - 48px)` |
| <720px | `＋`와 `≫`는 유지(탭 폭을 먼저 줄인다). 렌더 헤더의 `[소스 보기]` 라벨은 아이콘만 |
- 세로 예산: 툴바 48 + **탭 바 32** + 상태바 26 = 106px 고정. 최소 창 높이 480px에서 콘텐츠 374px 확보
- ⚠ **02 §9의 함정 재발 주의**: 그리드 아이템의 자동 최소 높이 때문에 에디터가 상태바를 밀어낸 결함이 있었다. 탭 바가 한 행 더 늘어나므로 **고정 높이 행(툴바·탭 바·상태바)을 먼저 배치하고 콘텐츠에 `min-height: 0`** 을 주는 규칙을 그대로 지킬 것

## 7. 데이터 요구 (코어·시니어 전달)

02 §6에 이어서. 여전히 HTTP가 아니라 앱 내부 호출이지만 화면이 요구하는 계약은 같다.

### 7.1 탭 (REQ-012)
| 화면 | 필요 데이터 | 비고 |
|------|-----------|------|
| W-11 탭 목록 | `tabs -> [{id, displayName, rootPath, indexState, dirtyFileCount, disambiguator?}]` **순서 있음** | `indexState`는 기존 §6 5상태 그대로(탭별). `disambiguator`는 이름 충돌 시에만 채운다 |
| 탭 활성화 | `activeTabId` + `activate(id)` — **동기·즉시** | AC-2. 인덱스는 메모리에 상주하므로 I/O 대기가 없어야 한다 |
| 프로젝트 열기 | `openProject(rootPath) -> .opened(tabId) \| .activatedExisting(tabId) \| .failed(OpenError)` | **AC-5를 반환형으로 구분**해 달라. UI가 "새 탭"과 "기존 탭 활성화"의 문구를 갈라야 한다 |
| 탭 닫기 | `dirtyFiles(tabId) -> [path]` → `saveAll(tabId)`(nvim 위임) → `closeTab(id)` | AC-3: 닫힌 뒤 그 탭의 인덱스·감시자·편집 버퍼가 모두 해제됨을 **테스트로 보장**해 달라(고아 없음) |
| 복원 | `restoreTabs() -> {restored:[{id, rootPath}], activeIndex, missing:[{displayName, rootPath, reason}]}`, `reason = notFound \| noPermission` | AC-4·AC-6. **사유 마스킹 금지**(02 §6의 태도 계승) |
| 재정렬 | `reorderTabs([id]) `— 즉시 영속 | AC-4 |
| 인덱싱 스케줄 | **활성 탭 우선**, 나머지는 배경 순차 | F-13-3. 복원 직후 5개가 동시에 CPU를 먹으면 활성 탭이 늦어진다 |
| 이벤트 | 탭별 인덱스 진행·더티 변화는 **이벤트 스트림**(폴링 금지) | 02 §6 규칙 계승 |
| 계측 | 탭 1개 기준선 대비 **탭당 메모리 증가분**을 측정할 수 있는 훅 | REQ-NF-002 재정의(01b) — UI 표시는 없다 |

### 7.2 렌더 (REQ-013 · INV-6)
| 화면 | 필요 데이터 |
|------|-----------|
| 렌더 가능 판정 | `isRenderable(path) -> Bool` — `.md` `.markdown` `.html` `.htm` |
| 렌더 | `renderDocument(path, tabId) -> Result<Rendered, RenderError>` |
| 성공 페이로드 | `Rendered { safeHTML, blocked: [Blocked], scriptDependentHint: Bool }` |
| 차단 항목 | `Blocked { kind, count, host?, path?, alt? }`, `kind = remoteImage \| script \| remoteStyle \| remoteFont \| frame \| outsideRoot` — **W-15 팝오버의 6분류와 1:1** |
| 실패 | `RenderError = unreadable(reason) \| undecodable \| tooLarge(bytes, limit: 2MB)` — **W-14 실패 카드 3종과 1:1.** 빈 성공으로 위장 금지(02 §6 정규식 에러 규칙과 같은 태도). **부분 렌더로 잘라서 성공 반환하지 마라** — 자를 거면 `tooLarge`로 실패시켜 UI가 사유를 말하게 한다 |
| 빈 파일 | 실패가 아니라 `Rendered`(빈 본문) + UI가 빈 문서 카드 표시 |
| 갱신 | 저장 완료 이벤트(02 §6 `save`)로 해당 경로 캐시 무효화 → 렌더 보기가 열려 있으면 재렌더 |
| 로컬 이미지 | 루트 안 상대·절대 경로만 해석. **루트는 `tabId`의 루트**(INV-5) |
| 링크 해석 | 앵커 / 루트 안 파일 / 루트 밖 / 외부 URL 4분류를 코어가 판정해 UI에 알려 준다 |

## 11. 프론트엔드 구현 노트 (SwiftUI)

1. **행 순서를 고정 높이부터**: `VStack(spacing: 0) { 툴바(48) ; 탭바(32) ; 콘텐츠(.frame(maxHeight: .infinity)) ; 상태바(26) }`. 02 §9에서 에디터가 상태바를 밀어낸 결함이 있었다 — 행이 하나 늘었으니 같은 함정을 다시 밟기 쉽다
2. **렌더 표면은 Neovim 그리드를 리사이즈하지 않는다.** 같은 프레임 위에 `ZStack`으로 얹고 `opacity`/`isHidden`으로 전환한다. 그리드 크기가 바뀌면 nvim 전면 리드로가 발생한다
3. **탭 라벨 말줄임은 `.truncationMode(.middle)`**
4. **숫자 포맷은 한 곳에서**: 탭 툴팁의 `1,284/4,812`와 상태바 칩·W-10 팝오버가 같은 포매터를 써야 한다. 이 빌드에서 이미 칩과 팝오버가 갈렸던 전례가 있다(저널 기록)
5. **탭 전환은 뷰 재생성이 아니라 상태 스왑**이어야 AC-2의 "즉시"가 지켜진다. 탭별 상태를 `@Observable` 모델로 들고 활성 id만 바꾼다
6. **차단 목록은 렌더 결과와 함께 한 번에** 받는다(렌더 후 DOM을 다시 훑지 않는다) — 코어 계약 §7.2
7. **탭 바 접근성**: `accessibilityRole(.tabGroup)` 상당 구조 + 각 탭에 `accessibilityValue(선택됨/선택 안 됨)`
8. **툴바 버튼에 "눌림" 스타일이 아직 없다.** 1차 프로토타입 `styles.css`에는 `.seg button.on`(모드 세그먼트)만 있고 `.tb-btn.on`이 없다 — 즉 **툴바 토글 버튼의 눌린 상태를 그린 전례가 없다**. 렌더 토글은 그 상태가 AC-3의 표시 ①이므로, 채움(accent) 스타일을 실제로 구현해야 한다(프로토타입 `styles-2b.css`에 추가해 뒀다). 기존 `패널 ⌥⌘0` 버튼도 `aria-pressed`만 있고 시각 표시가 없었다 — 같은 스타일을 적용하면 함께 해결된다

## 12. 리더 판정 (§10 확인 요청 8건 — 2026-08-30)

PD가 올린 미결 항목에 대한 결정. **이후 구현·QA는 이 판정을 따른다.** (02 §11과 같은 형식)

1. **탭 1개일 때도 탭 바를 표시한다.** PD 판단 확정 + 리더가 근거를 하나 더 붙였다: **C-1로 툴바 프로젝트 팝업을 제거하기로 했으므로, 탭 1개에서 탭 바까지 숨기면 "어떤 프로젝트가 열려 있는지" 가 화면 어디에도 남지 않는다.** 관례(Safari·Finder·Terminal은 1탭에서 숨긴다)를 따르다 정보를 잃는 것이다. 레이아웃 점프가 없다는 것은 부수 이득. **QA는 이 기준으로 AC-1을 검증한다.**
2. **더티 탭 닫기 확인 시트(W-13) = 넣는다.** REQ에 문장이 없어도 **데이터 유실은 막는다.** 근거는 W-13 항목에 3가지로 적었다(AC-3의 정리를 손실 없이 읽음 · Neovim `E37` 과의 약속 일치 · 이 빌드에서 닫은 같은 형태의 결함 2건).
3. **`⌘W` = 탭 닫기 / `⇧⌘W` = 창 닫기로 변경(C-2) = 승인.** 탭이 있는 맥 앱에서 `⌘W`가 창을 닫으면 사용자가 탭 하나 닫으려다 작업을 통째로 잃는다. 마지막 탭 닫기 = 웰컴 화면 복귀도 승인.
4. **실행 중 프로젝트 루트 소실 = 설계하지 않는다(승인).** 지금 범위 밖. 단 **저널에 "미설계"로 명시 기록**한다 — 나중에 "왜 없지"가 나올 자리다.
5. **렌더 가능한 파일의 기본 보기 = 렌더(D-C) = 승인.** 사용자가 소스로 바꾸면 그 파일에 대해 기억하는 것도 승인.
6. **렌더 크기 상한 2MB = 승인.** 단 **조용히 자르지 말 것** — 상한에 걸리면 무엇이 왜 안 보이는지 화면에 나온다(W-14 크기 초과 카드, §7.2 `tooLarge`).
7. **용어집 등재(`탭` · `렌더 보기` · `소스 보기` · `샌드박스`) = 승인.** 리더(PM 겸임)가 `01b_requirements.md`에 넣는다.
8. **툴바 프로젝트 팝업 제거(C-1) = 승인.** 위 1번의 근거가 됐다.
