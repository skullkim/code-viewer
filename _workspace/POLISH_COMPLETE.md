# 남은 계획 전체 — 완료 인증

**인증 시각:** 2026-09-06 · **릴리스:** v0.3.0

사용자 지시는 "계획한거 멈추지 말고 싹다해" 였다. 여섯 항목 전부 끝났고, 계획에 없던
결함 하나를 게이트가 잡아 같이 고쳤다.

| # | 항목 | 어떻게 확인했나 |
|---|---|---|
| 1 | 편집기 주변부 색 | 대비 계산 + 라이트/다크 스크린샷 |
| 2 | 멈춘 줄 강조 | 실제 JVM 에 붙어 스크린샷 (6행 화살표 + 줄 강조) |
| 3 | 브레이크포인트 거터 표시 | 같은 화면에서 8행 빨간 점 확인 |
| 4 | 스텝 over/into/out | 라이브 — 5행에서 한 줄 실행 → 6행 |
| 5 | 중복 테스트 정리 · 게이트 입력 문서화 | 이관한 단언을 일부러 깨뜨려 잡히는지 확인 |
| 6 | v0.3 릴리스 | DMG 를 받아 격리 붙였다 떼고, 앱을 띄워 메뉴를 읽음 |
| + | 파일 감시자 use-after-free | 크래시 스택으로 원인 확정, 3회 연속 통과 + 새 크래시 0건 |

## 이번 증분에서 배운 것

**게이트가 계획에 없던 결함을 잡았다.** `swift test` 가 SIGSEGV 로 죽었고 스택이
`FSEvents → fileSystemWatcherCallback → 0x0` 이었다. 스트림이 감시자를 약하게 들고 있어서
해제 뒤 도착한 이벤트가 죽은 객체를 되살렸다. 앱에서는 탭을 닫는 순간이 같은 창인데,
그 크래시 리포트는 사용자 손에 있고 우리는 못 본다.

**관측 도구를 세 번 의심해야 했다.**
- `strings` 는 ASCII 만 뽑는다 — 한글 메뉴 항목이 전부 0건으로 나왔다.
- 바이트 직접 검색도 거짓 0을 냈다("계속 실행" 은 화면에서 이미 봤는데 0건).
- 결국 **앱을 띄워 메뉴를 읽는 것**만이 판정이 됐다.
- positive/negative control 을 같이 돌리지 않았으면 "기능이 안 들어갔다"고 잘못 보고했다.

**불변식을 내 편의로 깎지 않았다.** 스텝 단축키를 IntelliJ 대로 F8/F7 로 넣었더니 게이트가
막았다 — 앱은 ⌘ 조합만 가져간다(REQ-011 AC-2). 규칙이 옳아서 단축키를 바꿨다. 구멍이 하나
생기면 다음 사람이 둘째를 뚫는다.
