## REQ-012: 여러 프로젝트를 동시에 열고 탭으로 본다

사용자 요청 원문: *"여러 프로젝트 동시에 키고, 프로젝트는 상단에 탭이 나타나서 탭 단위로 보고 싶어"*

| # | 수용 기준 |
|---|---|
| AC-1 | 프로젝트를 **여러 개 동시에** 열 수 있다. 창 상단에 프로젝트당 **탭**이 표시된다 |
| AC-2 | 탭을 선택하면 그 프로젝트의 **트리·에디터·검색 결과**로 전환된다. **재인덱싱 대기 없이 즉시** 전환된다 (사용자 결정: 열린 프로젝트의 인덱스를 전부 메모리에 유지) |
| AC-3 | 탭을 닫으면 그 프로젝트의 인덱스와 편집 세션이 **정리된다** — 고아 프로세스·메모리 잔존 없음 |
| AC-4 | 앱을 껐다 켜면 **열려 있던 탭 목록과 활성 탭이 복원된다** (사용자 결정) |
| AC-5 | 이미 열린 프로젝트를 다시 열면 **새 탭을 만들지 않고 기존 탭을 활성화**한다 |
| AC-6 | 사라진 경로의 탭은 복원 시 **조용히 버리지 않고** 사용자에게 알린 뒤 목록에서 제거한다 (기존 REQ-001 AC-3 의 태도와 같다) |

### INV-5 (신규): 탭 간 격리
한 탭에서의 조작(파일 열기·검색·편집·인덱싱)은 **다른 탭의 상태를 바꾸지 않는다.**
탭은 프로젝트 하나에 대응하고, 그 프로젝트의 트리·검색·편집 상태를 각자 소유한다.

### INV-3 과의 관계 (유지)
편집은 여전히 **Neovim 을 통해서만** 일어난다. 탭이 여럿이어도 이 불변식은 그대로다.

### ⚠ 기존 결정과 충돌하는 지점 — 시니어가 ADR 로 판정할 것
1. **`ProjectWorkspace` 불변식**(`docs/adr/0106`)은 "인덱스와 편집기가 **한** 프로젝트를 함께 따라간다"를 타입으로 강제한다. 탭이 여럿이면 그 전제가 바뀐다. **폐기가 아니라 탭 단위로 좁히는 것**이 자연스러워 보이나, 판정은 시니어 몫이다.
2. **편집 세션 모델**: 탭마다 Neovim 프로세스를 하나씩 둘 것인가, **하나의 Neovim 이 여러 버퍼·작업 디렉토리를 다룰 것인가**. 후자가 메모리에 유리하고 Neovim 이 원래 지원하는 방식이다. **ADR 로 결정하고 근거를 남길 것.**
3. **REQ-NF-002 메모리 예산 재정의**: 기존 "유휴 ≤150MB" 는 **프로젝트 1개 기준**으로 다시 읽는다. 사용자가 "전부 유지"를 택했으므로 총량은 열린 프로젝트 수에 비례한다.
   → **탭당 증가분을 실측해 기록한다.** 기존 실측: 앱 기준선 95MB, 인덱스 비용 약 19MB/25,000심볼.
   → 이 앱의 존재 이유가 "IntelliJ 대비 1/10" 이므로, **탭당 증가분이 그 논거를 유지하는지**를 수치로 보인다.

### ⚠ AC-4(탭 복원)의 숨은 전제 — security-scoped bookmark (backend-senior 실측)
macOS 는 **앱이 사용자 선택 없이 보호된 경로에 접근할 때** 권한(TCC)을 막는다. 그리고
**AC-4 가 정확히 그 상황이다** — 저장된 경로로 여는 것이지 사용자가 그 실행에서 고른 게 아니다.

**실측: 엔진·앱에 security-scoped 관련 코드가 0줄이다.**
```
grep "startAccessingSecurityScopedResource|bookmarkData" Sources/ → 0
```
→ **지금 구조로 탭 복원을 만들면 `~/Documents` 아래 프로젝트는 재시작 후 빈 프로젝트로 열리거나
실패한다.** QA 가 첫 실행에서 본 "조용한 실패"가 **재시작마다** 재현될 수 있다.

**요구사항으로 못박는다:**
| # | 수용 기준 |
|---|---|
| AC-7 | 사용자가 폴더를 고를 때 **security-scoped bookmark 를 저장**하고, 복원 시 그것으로 접근 권한을 되찾는다 |
| AC-8 | **스코프는 탭이 열려 있는 내내 유지된다.** 여는 순간만 열고 닫으면 이후 재스캔·파일 감시가 **조용히** 실패한다 |
| AC-9 | 권한을 되찾지 못한 탭은 **조용히 빈 프로젝트로 열지 않는다** — AC-6 과 같은 태도로 사유를 알린다 |

**소유권**: 북마크 저장·복원은 지속성이므로 **앱(프론트)**. 다만 **"탭 수명 동안 유지"** 제약은
엔진이 그 URL 로 계속 스캔·감시하기 때문에 생긴다 — **계약 합의 때 명시적으로 다룬다.**

**부분 방어(완전하지 않음)**: `indexStatistics().fileCount == 0` 이면 **"열렸는데 파일이 하나도
없다"**를 앱이 알 수 있다. 진짜 빈 레포와 구분은 못 하지만 **조용히 정상인 척하는 것보다 낫다.**

## REQ-013: 마크다운·HTML 렌더링

사용자 요청 원문: *"markdown, html 렌더링 기능도 넣어줘"*

| # | 수용 기준 |
|---|---|
| AC-1 | `.md` 파일을 열면 **렌더된 문서**를 볼 수 있다 |
| AC-2 | `.html` 파일을 열면 **렌더된 페이지**를 볼 수 있다 |
| AC-3 | **원본(소스)과 렌더 보기를 전환**할 수 있다. 어느 쪽인지 화면에 드러난다 |
| AC-4 | 렌더 보기는 **읽기 전용**이다. 편집은 소스 보기(Neovim)에서만 — **INV-3 유지** |
| AC-5 | 소스를 편집·저장하면 렌더 보기가 **갱신된다** |
| AC-6 | 렌더할 수 없는 파일(깨진 마크업 등)에서 **빈 화면을 보여주지 않는다** — 무엇이 문제인지 알린다 |

### INV-6 (신규): 렌더는 샌드박스다
**임의의 레포에 있는 HTML 을 그리는 것은 보안 표면이다.** 사용자가 신뢰하지 않는 저장소를 열 수 있다.
- **원격 리소스 로드 차단**(이미지·스크립트·스타일시트·폰트 — 네트워크 요청 없음)
- **스크립트 실행 차단**
- **로컬 파일 접근은 열린 프로젝트 루트 안으로 제한**
- 마크다운 렌더도 같다 — 마크다운은 HTML 을 품을 수 있다
→ **차단이 기본값이고, 완화는 사용자가 명시적으로 요청할 때만.** 이 판단은 협상 대상이 아니다.

### 설계 메모 (PD·시니어에게)
- **전환 방식**은 설계 판단에 맡긴다(토글 / 나란히 보기). 다만 **에디터 그리드는 Neovim 소유**이므로 렌더 보기는 그 위에 얹는 별도 표면이어야 한다.
- 렌더 보기에서도 **정의 이동·참조 검색 같은 코드 내비게이션이 필요한가**는 열어 둔다 — 필요 없다고 보면 그 근거를 적을 것.
- `.md`·`.html` 은 현재 **인덱싱 대상 언어가 아니다**(Kotlin·Java·TS·JS). 렌더는 인덱싱과 무관한 별개 기능이다.

## 용어집 추가 (PM — 기존 `01_requirements.md` 용어집에 더한다)

| 용어 | 뜻 | 왜 이 이름인가 |
|---|---|---|
| **탭** | 열린 프로젝트 하나에 대응하는 상단 항목. 그 아래 트리·에디터·패널·상태바 전부가 그 탭 소유다 | 사용자가 요청한 말 그대로다. "프로젝트 탭"으로 늘려 부르지 않는다 — 이 앱에서 탭은 프로젝트 말고 없다 |
| **렌더 보기** | 마크다운·HTML 을 사람이 읽는 형태로 그린 화면. **읽기 전용** | "미리보기"를 쓰지 않는다 — 미리보기는 "곧 다른 것이 된다"는 뜻이고, 이건 최종 표시다 |
| **소스 보기** | 파일의 원문을 Neovim 그리드로 보는 기본 화면. **편집은 여기서만** | "편집 보기"가 아니다 — 편집 여부가 아니라 무엇을 보고 있는지가 구분점이다 |
| **샌드박스** | 렌더 보기가 원격 리소스·스크립트를 차단하고 로컬 접근을 프로젝트 루트로 제한하는 상태(INV-6) | 화면에도 이 말을 그대로 쓴다(`🛡 샌드박스` 칩). 사용자가 보는 말과 문서의 말이 같아야 한다 |

**신규 도메인 용어는 이 표에 등재된 것만 쓴다.** 코드·화면·문서가 같은 말을 쓰지 않으면 같은 것을
가리키는지 아무도 확신하지 못한다.
