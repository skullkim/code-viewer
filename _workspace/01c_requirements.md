# 요구사항 증분 3 — 편집기 상호작용 (REQ-015 ~ REQ-017)

**전제**: `01_requirements.md`(REQ-001~011) · `01b_requirements.md`(REQ-012~014)가 인증 완료된 상태에서의 증분.
**사용자 요구 원문**: *"빔 모드에서 gd를 누르면 해당 클래스를 사용하는 모든 곳이 나열됐으면 좋겠어. 네오빔 별도로 세팅 안 해도 IntelliJ처럼 하이라이트되고, 마우스 클릭 드래그도 동작하면 좋겠어."*

**⚠ 원문에서 한 곳이 대화로 정제됐다**: `gd`를 "사용처 목록"으로 해달라는 요구였으나, 확인 결과 **`gd`는 정의로 가고 `gr`이 사용처**로 정했다. 사용자가 고른 근거는 **"다른 Vim 환경과 손이 같아지는 쪽"**이다.

**⚠⚠ 그 선택지를 제시할 때 리더가 근거를 틀리게 적었다 — 정정한다.** 나는 `gr`이 *"LSP·최신 Neovim 관례"*라고 썼는데, **Neovim 0.12의 실제 기본 매핑은 `grr`**이고 `gr`은 그 접두사다(`gra gri grn grr grt grx`가 전부 `vim.lsp.buf.*`). 백엔드 시니어가 실측으로 잡았다 — `gr`을 그대로 매핑하면 `timeoutlen`만큼 기다려 **누를 때마다 1032ms 멈춘다**(`gd`는 21ms).

**그럼에도 `gr`을 유지한다. 근거가 바뀌었을 뿐 선택은 유효하다:**
- 사용자가 고른 것은 *"손이 같아지는 쪽"* 이었고 **1초 지연은 손이 달라지는 것**이다
- `grr`은 관례에 맞지만 키를 하나 더 누른다 — 사용자가 원한 건 빠른 접근이었다
- 지연의 원인인 Neovim 기본 `gr*` 6개는 **이 앱 안에서 죽은 키다**(실측: `vim.lsp.get_clients() = 0` — LSP를 붙이지 않는다). 우리 세션에서만 제거하면 **0ms**

**교훈**: 근거가 틀렸다고 결론이 자동으로 틀린 것은 아니다. 다만 **근거를 실측으로 갈아 끼우기 전까지는 그 결론을 신뢰할 수 없었다.**

## REQ-015: Vim 모드 `gd` / `gr`

Vim 모드에서 nvim 설정 없이 정의 이동과 사용처 목록을 키로 쓴다.

| AC | 내용 |
|---|---|
| AC-1 | 노멀 모드에서 **`gd`** 를 누르면 커서 아래 심볼의 **정의로 이동**한다 — 프로젝트 전체 범위(⌘B와 같은 동작·같은 결과) |
| AC-2 | 노멀 모드에서 **`gr`** 를 누르면 커서 아래 심볼을 **사용하는 모든 곳의 목록**이 참조 패널에 뜬다 (⇧⌘B와 같은 결과) |
| AC-3 | `⌘B`·`⇧⌘B`는 **그대로 동작한다** — 키가 늘어난 것이지 옮겨간 것이 아니다 |
| AC-4 | 정의가 여럿이면 **⌘B와 같은 후보 목록**이 뜬다 (REQ-005의 기존 동작을 재사용) |
| AC-5 | 커서 아래가 심볼이 아니면 **아무 일도 일어나지 않는 대신 이유를 말한다** — 조용히 무시하지 않는다 |
| AC-6 | **사용자의 `~/.config/nvim`에 `gd`/`gr` 매핑이 이미 있으면 그것을 덮어쓰지 않는다** |
| AC-7 | **Neovim 자신의 기본 `gr*` 매핑은 우리 세션에서 제거한다** — 사용자 것과 구별해서. (실측: 사용자 매핑 `sid=3`+스크립트 경로 / Neovim 기본 `sid=-8`+스크립트 없음 / 미매핑 — **세 상태가 갈린다**) |
| AC-8 | **사용자가 자기 `gr*` 매핑을 갖고 있으면 `gr`을 매핑하지 않는다.** 그 경우 지연을 없애려면 AC-6을 깨야 하므로 **AC-6이 이긴다.** 그리고 **왜 `gr`이 없는지 사용자에게 말한다 — 조용히 넘어가지 않는다** |

> **AC-6의 이유**: 이 앱은 사용자 nvim 설정을 침범하지 않는다(기존 설계 원칙). 자기 매핑을 쓰는 사용자에게 우리 매핑이 이기면 그 원칙이 깨진다.
>
> **AC-7과 AC-6이 반대로 보이지만 기준은 하나다 — 누구의 것인가.** 사용자 것은 손버릇이라 이긴다. Neovim 기본은 이 앱 안에서 **아무 일도 못 하는 죽은 키**라(LSP 미부착) 비켜도 잃는 것이 없다.
>
> **AC-8이 그 기준의 경계다.** 사용자 `grr`이 있으면 우리 `gr`은 그 접두사가 되어 지연이 되돌아온다. 둘 다 만족하는 길이 없으므로 **느리게 동작시키는 대신 안 하고 이유를 말한다** — 지난 빌드에서 여덟 번 만난 것이 *"조용히 아무 일도 안 일어남"*이었다.

## REQ-016: 구문 강조 + 같은 심볼 강조

nvim을 따로 설정하지 않아도 코드가 색을 갖는다.

| AC | 내용 |
|---|---|
| AC-1 | **지원 언어 파일을 열면 구문 강조가 보인다** — 키워드·문자열·주석·숫자·타입 이름이 서로 다른 색 |
| AC-2 | **커서를 심볼에 두면 그 파일 안의 같은 심볼이 함께 강조**된다. 커서가 움직이면 따라온다 |
| AC-3 | 강조 색은 **02_design.md의 디자인 토큰**에서 온다 — 파일마다·테마마다 임의 색을 쓰지 않는다 |
| AC-4 | **지원하지 않는 언어(예: `.py`, `.go`)는 강조 없이 평문으로 보인다** — 깨지거나 잘못된 색이 붙지 않는다 |
| AC-5 | 강조가 **편집을 느리게 하지 않는다** — 타이핑 응답이 강조 없을 때와 체감상 같다 |
| AC-6 | **사용자 nvim 설정에 색 구성(colorscheme)이 있어도 앱의 토큰이 이긴다** — 앱 안에서는 앱의 테마가 일관돼야 한다 |

> **AC-6은 AC 하나가 아니라 판단이다.** REQ-015 AC-6(매핑은 사용자 것이 이긴다)과 방향이 반대인데, 이유가 다르다: **키는 손버릇이라 사용자 것이 이겨야 하고, 색은 화면 일관성이라 앱 것이 이겨야 한다.** 시니어가 다르게 보면 ADR로 반론할 것.

## REQ-017: 마우스 클릭·드래그

| AC | 내용 |
|---|---|
| AC-1 | 편집 영역을 **클릭하면 그 위치로 커서가 간다** (노멀·삽입 모드 모두) |
| AC-2 | **드래그하면 비주얼 선택**이 된다. 놓으면 선택이 유지된다 |
| AC-3 | 선택된 범위는 **화면에 보인다** (선택 배경색) |
| AC-4 | 마우스로 만든 선택에 **Vim 명령이 그대로 먹는다** — 예: 드래그 후 `d`로 삭제, `y`로 복사 |
| AC-5 | **스크롤 휠·더블클릭 단어 선택은 이번 범위 밖이다** (사용자 선택) |

## 불변식

| INV | 내용 |
|---|---|
| **INV-7** | **사용자의 `~/.config/nvim`을 수정하지 않는다.** 매핑·옵션은 앱이 띄운 세션에만 적용한다 (기존 설계 원칙의 명문화) |
| **INV-8** | **강조는 파생물이다.** 강조 실패가 편집을 막지 않는다 — 색이 안 붙어도 파일은 열리고 편집된다 |

## 수용 시나리오

**SC-10 (gd/gr)**
```
Given  TypeScript 프로젝트에서 UserService 를 쓰는 파일이 3개 있다
When   UserService 라는 단어에 커서를 두고 노멀 모드에서 gr 을 누른다
Then   참조 패널에 3개 파일의 사용처가 나열된다 (⇧⌘B 와 같은 목록)
And    gd 를 누르면 UserService 의 정의로 점프한다
```

**SC-11 (같은 심볼 강조)**
```
Given  한 파일 안에 user 라는 이름이 5곳에 있다
When   그중 하나에 커서를 둔다
Then   다섯 곳이 전부 강조된다
When   커서를 other 로 옮긴다
Then   user 강조가 사라지고 other 가 강조된다
```

**SC-12 (마우스 선택 후 Vim 명령)**
```
Given  파일이 열려 있고 노멀 모드다
When   3번째 줄 5열에서 5번째 줄 10열까지 드래그한다
Then   그 범위가 비주얼 선택으로 보인다
When   d 를 누른다
Then   그 범위가 삭제된다
```

**SC-13 (미지원 언어 — 반대 방향)**
```
Given  Python 파일을 연다 (tree-sitter 문법 없음)
When   파일이 화면에 뜬다
Then   평문으로 보인다 — 잘못된 색이 붙거나 깨지지 않는다
And    편집·저장·검색은 정상 동작한다 (INV-8)
```
