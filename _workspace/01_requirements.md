# 요구사항 명세: code-navigator-mac

## 1. 개요
- 목표: **맥 네이티브 코드 에디터 겸 내비게이터**. IntelliJ 수준의 심볼 인덱싱(정의 이동·참조 검색)을 IntelliJ보다 훨씬 가볍게 제공하고, 편집은 **진짜 Neovim**이 담당한다.
- 주 사용자: 사용자 본인(로컬 단일 사용자). AI가 만든 코드를 읽고 확인하고, 필요하면 그 자리에서 고친다.
- 핵심 유스케이스: 레포 열기 → 트리·검색으로 파일 찾기 → Vim 조작으로 읽고 편집 → 심볼에서 정의로 점프 → 참조 확인 → 저장. 파일이 바뀌면 인덱스가 자동으로 따라온다.
- 배경: 웹앱판 code-navigator(312 테스트 통과)의 인덱싱 엔진을 네이티브로 이식한다. 서버·HTTP·브라우저가 사라지고 앱 내부 함수 호출이 된다. **웹앱을 대체한다.**
- 성능 목표 근거(실측): IntelliJ는 앱 4.1GB + 인덱스 448MB + 메모리 1~2GB. 웹앱판은 메모리 131MB에 7천 파일 레포 인덱싱 3초. 네이티브는 Node 런타임이 빠져 더 가벼워야 한다.

## 2. 범위
- In-scope: 프로젝트 열기·전환, 심볼 인덱싱(Kotlin·Java·TS·JS), 파일 트리, **Neovim 임베드 편집**, 정의로 이동, 참조 목록, 심볼 퍼지 검색, 전문 텍스트 검색, 파일 변경 자동 재인덱싱, 네이티브 앱 셸(창·메뉴·단축키).
- Out-of-scope: LSP 수준 타입 해석(참조는 이름 기반 근사), 디버거·빌드 실행·터미널, 원격/SSH 편집, 플러그인 시스템(자체), 다중 사용자·동기화, 앱 서명·배포(개인 로컬 실행), Neovim 자체 기능 재구현(임베드로 위임).

## 3. 도메인 용어집 + 개념 모델
- **프로젝트(project)**: 열어놓은 로컬 레포 루트 경로 하나.
- **심볼(symbol)**: 이름을 갖는 선언 — 클래스, 인터페이스, enum, object, 함수/메서드, 프로퍼티/필드, 타입 별칭.
- **정의(definition)**: 심볼이 선언된 위치(파일 경로 + 라인). 동명 정의가 여러 개일 수 있다.
- **참조(reference)**: 심볼 이름이 사용된 위치. **이름 기반 근사**이며(타입 해석 없음) 동명 이의어가 섞일 수 있음을 UI가 고지한다.
- **인덱스(index)**: 소스에서 생성된 파생물. 정방향(파일→심볼)·역방향(이름→위치) 두 방향. 앱 메모리에 존재하며 언제든 전량 재생성 가능하다.
- **편집 세션(edit session)**: 임베드된 Neovim 인스턴스가 관리하는 버퍼·모드·레지스터 등 편집 상태 전체. 앱은 이를 대행하지 않고 Neovim에 위임한다.
- **더티 버퍼(dirty buffer)**: Neovim에 열려 있고 디스크와 내용이 다른 버퍼.
- 개념 모델: 프로젝트 1 ─ N 파일, 파일 1 ─ N 심볼(정의), 심볼 이름 1 ─ N 정의 위치, 심볼 이름 1 ─ N 참조 위치, 프로젝트 1 ─ 1 편집 세션(Neovim 인스턴스).

## 4. 기능 요구사항

### REQ-001: 프로젝트 열기·전환
- 영역: both / 우선순위: must
- 수용 기준:
  - [ ] AC-1: 폴더 선택(맥 표준 파일 선택 대화상자)으로 프로젝트를 열면 트리가 표시되고 인덱싱이 시작되며 진행 상태가 보인다.
  - [ ] AC-2: 최근 연 프로젝트 목록에서 전환할 수 있고, 전환 시 트리·에디터·검색 결과가 해당 프로젝트로 바뀐다.
  - [ ] AC-3: 존재하지 않거나 접근 불가한 경로면 명확한 에러를 표시하고 이전 상태를 유지한다.
  - [ ] AC-4: 인덱싱은 `.gitignore`와 기본 제외 목록(node_modules, build, dist, .git, target 등)을 존중한다.

### REQ-002: 심볼 인덱싱 (Kotlin·Java·TS·JS)
- 영역: backend / 우선순위: must
- 수용 기준:
  - [ ] AC-1: Kotlin/Java에서 class·interface·enum·object, 함수/메서드, 프로퍼티/필드가 이름·종류·파일:라인으로 추출된다.
  - [ ] AC-2: TS/JS에서 class·interface·enum·type alias, 함수(선언·화살표 상수), 메서드, export 상수가 추출된다.
  - [ ] AC-3: 미지원 언어 파일은 에러 없이 스킵하되 전문 검색 대상에는 포함된다.
  - [ ] AC-4: 파싱 실패 파일은 그 파일만 스킵하고 로그를 남긴다 — 전체 인덱싱이 중단되지 않는다.

### REQ-003: 파일 트리
- 영역: frontend / 우선순위: must
- 수용 기준:
  - [ ] AC-1: 디렉토리를 펼치면 하위 항목이 지연 로드되고, 파일을 선택하면 에디터에 열린다.
  - [ ] AC-2: 제외 목록·`.gitignore` 대상은 트리에 나타나지 않는다.
  - [ ] AC-3: 현재 편집 중인 파일이 트리에서 강조된다.

### REQ-004: Neovim 임베드 편집 (모든 Vim 기능)
- 영역: both / 우선순위: must
- 설명: 편집기는 자체 구현이 아니라 **임베드된 Neovim 프로세스**다. 모드·모션·오퍼레이터·텍스트 오브젝트·레지스터·마크·매크로·ex 명령·undo 트리 등 Vim 기능은 Neovim이 제공한다.
- 수용 기준:
  - [ ] AC-1: 앱 시작 시 Neovim이 `--embed`로 기동되고 RPC로 연결된다. 실패하면(미설치·버전 불일치) 명확한 안내를 표시한다(무반응 금지).
  - [ ] AC-2: 키 입력이 Neovim에 전달되고 화면(그리드·커서·모드)이 반영된다 — 노멀/삽입/비주얼/명령 모드가 정상 동작한다.
  - [ ] AC-3: 사용자의 기존 설정(`~/.config/nvim`)이 그대로 적용된다 — 설정·플러그인을 앱이 가로채지 않는다.
  - [ ] AC-4: `:w` 저장이 실제 파일에 반영되고, 저장 후 그 파일이 재인덱싱된다(REQ-008과 연결).
  - [ ] AC-5: Neovim 프로세스가 죽으면 앱이 감지해 알리고 재기동 수단을 제공한다(조용한 먹통 금지).

### REQ-005: 정의로 이동
- 영역: both / 우선순위: must
- 수용 기준:
  - [ ] AC-1: 커서 위치 심볼에 대해 정의 이동을 요청하면(단축키 및 Vim `gd` 계열 매핑) 정의 위치로 이동해 그 라인이 보이도록 스크롤·강조된다.
  - [ ] AC-2: 동명 정의가 여러 개면 후보 목록을 띄우고 선택 시 이동한다(키보드 조작 가능).
  - [ ] AC-3: 인덱스에 없으면 "정의를 찾을 수 없음"을 알린다(무반응 금지).
  - [ ] AC-4: 이동 후 이전 위치로 되돌아갈 수 있다(Vim 점프 목록과 정합).

### REQ-006: 참조 목록
- 영역: both / 우선순위: must
- 수용 기준:
  - [ ] AC-1: 심볼의 사용 위치 목록(파일:라인 + 해당 줄 미리보기)이 표시되고 항목 선택 시 그 위치로 이동한다.
  - [ ] AC-2: 정의 위치는 "정의"로 구분 표시된다.
  - [ ] AC-3: "이름 기반 검색 — 동명 이의어 포함 가능" 안내가 상시 표시된다.
  - [ ] AC-4: 참조 0건이면 "참조 없음"을 표시한다.

### REQ-007: 심볼 퍼지 검색
- 영역: both / 우선순위: must
- 수용 기준:
  - [ ] AC-1: 이름 일부·약어로 부분 일치·순서 보존 퍼지 매칭 결과가 관련도순으로 나온다.
  - [ ] AC-2: 결과에 이름·종류·파일:라인이 표시되고 선택 시 정의로 이동한다.
  - [ ] AC-3: 키보드만으로 조작 가능(↑↓ 이동, Enter 선택, Esc 닫기).
  - [ ] AC-4: 결과 0건이면 "결과 없음"을 표시한다.

### REQ-008: 전문 텍스트 검색
- 영역: both / 우선순위: must
- 수용 기준:
  - [ ] AC-1: 리터럴 문자열 검색 결과가 파일:라인 + 미리보기로 나오고 선택 시 이동한다.
  - [ ] AC-2: 정규식 모드를 지원하고, 잘못된 정규식이면 에러 메시지를 낸다(빈 결과로 위장 금지).
  - [ ] AC-3: 제외 대상은 결과에 나오지 않는다.
  - [ ] AC-4: 대량 결과는 상한과 안내를 표시한다.

### REQ-009: 파일 변경 자동 재인덱싱
- 영역: backend / 우선순위: must
- 수용 기준:
  - [ ] AC-1: 파일이 저장·수정되면 디바운스 후 그 파일만 재인덱싱되고 새 심볼이 검색에 반영된다.
  - [ ] AC-2: 파일 삭제 시 그 파일의 심볼·참조가 인덱스에서 제거된다(유령 결과 금지).
  - [ ] AC-3: 파일 추가·이름 변경이 반영되고 옛 경로 잔재가 없다.
  - [ ] AC-4: 대량 변경(예: git checkout) 시 이벤트 폭주로 죽지 않고 전체 재스캔으로 폴백하며 진행 상태를 표시한다.
  - [ ] AC-5: **앱 내부 편집(Neovim `:w`)과 외부 변경 모두** 동일하게 반영된다.

### REQ-010: Vim 모드 토글 (Vim ↔ 표준 편집)
- 영역: both / 우선순위: must
- 설명: 편집 입력 방식을 전환한다. **버퍼·파일·undo 이력은 언제나 Neovim이 단독 소유**하고(INV-3), 전환되는 것은 **키 입력 해석 계층뿐**이다 — 두 에디터를 병존시키지 않아 상태 분기·저장 사고를 원천 차단한다.
- 수용 기준:
  - [ ] AC-1: **Vim 모드(기본)** — 키 입력이 가공 없이 Neovim에 전달된다. 모드·모션·오퍼레이터 등 REQ-004의 모든 기능이 그대로 동작한다.
  - [ ] AC-2: **표준 모드** — 맥 관례대로 동작한다: 화살표·Home/End·⌥/⌘ 조합 이동, 클릭으로 커서 이동, 드래그·⇧+이동으로 선택, ⌘C/⌘V/⌘X/⌘Z/⌘⇧Z, ⌘S 저장, 타이핑 즉시 삽입(모드 개념 없음).
  - [ ] AC-3: 토글 수단이 **둘 다** 있다 — 메뉴 항목과 단축키. 현재 모드가 화면에 항상 표시된다(어느 모드인지 몰라 키를 잘못 누르는 상황 금지).
  - [ ] AC-4: **모드 전환 시 편집 내용·커서 위치·undo 이력·더티 상태가 보존된다** — 같은 버퍼를 계속 쓰기 때문. 전환만으로 저장이 일어나지 않는다.
  - [ ] AC-5: 표준 모드에서 Vim 전용 키(`hjkl`·`:`·`i` 등)는 **일반 문자로 입력**된다(모드 혼선 금지). 반대로 Vim 모드에서 ⌘ 조합 앱 단축키(REQ-011)는 계속 동작한다.
  - [ ] AC-6: 선택한 모드가 재시작 후 복원된다.

### REQ-011: 네이티브 앱 셸
- 영역: frontend / 우선순위: must
- 수용 기준:
  - [ ] AC-1: `.app`으로 실행되며 표준 맥 창(리사이즈·전체화면·최소화)과 메뉴 막대를 갖는다.
  - [ ] AC-2: 주요 동작에 맥 표준 단축키가 있고(프로젝트 열기·심볼 검색·전문 검색), Neovim 입력과 충돌하지 않는다(수식키 조합 사용).
  - [ ] AC-3: 창 크기·분할 비율·최근 프로젝트가 재시작 후 복원된다.
  - [ ] AC-4: 다크/라이트 모드가 시스템 설정을 따른다.

## 5. 불변식 (INV)
- INV-1 (스테일 0): 디바운스 경과 후 인덱스가 가리키는 모든 위치는 실제 파일에 존재한다 — 삭제된 파일·지워진 심볼이 결과에 나오지 않는다.
- INV-2 (파생물 원칙): 인덱스는 소스에서 전량 재생성 가능하다. 인덱스 저장물이 없어도 재시작·재스캔으로 동일 상태가 복구된다.
- INV-3 (편집 단일 경로): **파일 수정은 오직 임베드된 Neovim을 통해서만 일어난다.** 앱 자체 코드가 대상 레포 파일을 직접 쓰지 않는다(인덱서·트리·검색은 읽기만). 편집 이력·undo·저장 책임은 Neovim에 있다.
  > 웹앱판의 "읽기 전용" 불변식을 대체한다 — 편집은 허용하되 경로를 하나로 좁혀 사고를 막는다.
- INV-4 (설정 비침범): 앱은 사용자의 `~/.config/nvim` 설정·플러그인을 수정하지 않는다.

## 6. 상태 전이표
- 인덱스: `없음 --프로젝트 열기--> 인덱싱중 --완료--> 최신 --파일변경--> 갱신중 --완료--> 최신`, `인덱싱중/갱신중 --대량변경--> 전체재스캔 --완료--> 최신`. 어느 상태에서든 조회 가능(직전 인덱스로 응답, UI에 갱신 중 표시).
- 편집 세션: `미기동 --앱시작--> 연결중 --성공--> 연결됨 --프로세스종료--> 끊김 --재기동--> 연결중`. `끊김` 상태에서는 편집 UI를 비활성화하고 안내를 표시한다(입력 유실 방지).

## 7. 비기능 요구사항
### REQ-NF-001: 성능 — 중형 레포(소스 ~5,000파일) 기준 초기 인덱싱 ≤10초, 단일 파일 증분 갱신 ≤500ms, 심볼 검색 응답 ≤100ms, 전문 검색 ≤2초.
### REQ-NF-002: 자원 — 유휴 시 메모리 ≤150MB(중형 레포 인덱싱 후), 앱 번들 ≤200MB. IntelliJ 대비 메모리 1/10 이하가 목표이자 존재 이유다.
### REQ-NF-003: 기동 — 앱 실행부터 조작 가능까지 ≤2초(인덱싱은 백그라운드).
### REQ-NF-004: 안정성 — 파싱 실패·권한 없는 파일·심링크 루프·Neovim 비정상 종료에서 앱이 죽지 않는다.
### REQ-NF-005: 의존성 — Neovim은 외부 설치 의존이다. 부재·버전 미달 시 기동 단계에서 명확히 안내한다(런타임 중 조용한 실패 금지).

## 8. 수용 시나리오
- SC-1 (REQ-005, 행복): 프로젝트를 열고 `SymbolIndex` 심볼에 커서를 두고 정의 이동하면 그 클래스 선언 위치로 이동·강조된다.
- SC-2 (REQ-005, 동명): 동명 함수가 3곳에 정의된 경우 후보 3건이 뜨고 선택 시 이동한다.
- SC-3 (REQ-004+009, 편집→인덱스): 파일에 새 함수를 추가하고 `:w`로 저장하면 2초 내 심볼 검색에서 그 이름이 검색된다.
- SC-4 (REQ-004, 설정 존중): 사용자의 기존 `~/.config/nvim` 설정(예: 커스텀 키맵)이 앱 안에서 그대로 동작한다.
- SC-5 (REQ-009, 대량): git checkout으로 수백 파일이 바뀌어도 앱이 죽지 않고 전체 재스캔 후 INV-1이 성립한다.
- SC-6 (REQ-008, 엣지): 정규식 모드에서 `([unclosed`를 입력하면 "잘못된 정규식" 에러가 표시된다(빈 결과 아님).
- SC-7 (REQ-004 AC-5, 불행): Neovim 프로세스를 강제 종료하면 앱이 감지해 "편집 세션 끊김"을 알리고 재기동 수단을 제공한다.
- SC-9 (REQ-010, 토글): Vim 모드에서 몇 줄 수정한 뒤 표준 모드로 전환해도 수정분·커서·undo가 유지되고, ⌘Z로 방금 편집을 되돌릴 수 있다.
- SC-8 (REQ-NF-002, 자원): 중형 레포 인덱싱 후 메모리가 150MB를 넘지 않는다(실측).

## 9. 가정
- 가정 A: Neovim은 사용자가 이미 설치한 것을 쓴다(현재 0.12.5 확인). 앱이 번들하지 않는다.
- 가정 B: 개인 로컬 실행 전용 — 앱 서명·공증·배포는 범위 밖.
- 가정 C: 지원 언어 확장(Swift·Python 등)은 후속. 추출기는 언어 추가가 쉬운 구조를 지향.
- 가정 D: 프리플라이트 실측 완료 — Swift 6.2.3+SPM, SwiftUI(Xcode 없이도 컴파일), Swift Testing(Xcode 설치 후), Neovim RPC 임베드 왕복 확인.
