## 1. 마운트 카운트 (기계적 — 화면 판정의 1차 관문)

정의부를 뺀 참조 수를 센다:

```bash
for v in PlaceholderPane MainWindowView StatusBarView ToolbarView FileTreeView EditorGridView \
         ProjectOpenView DefinitionCandidatesView EditSessionOverlayView ReferencePanelView \
         TextSearchPanelView SidePanelView; do
  n=$(grep -rn "$v(" Sources/ --include="*.swift" | grep -v "struct $v" | wc -l | tr -d ' ')
  printf "%-26s %s\n" "$v:" "$n"
done
```

**합격선: `PlaceholderPane` 이 0 이고, 나머지 화면 뷰가 각각 1 이상.**

**23:03 실측 — 미연결 9종.** 창에는 여전히 회색 판 3장이다.

| 미연결 뷰 | 막힌 요구사항 |
|---|---|
| **`EditorGridView`** | **REQ-004 AC-2 — 에디터 화면 그 자체(본체)** |
| `FileTreeView` | REQ-003 (파일 트리 전부) |
| `ProjectOpenView` | REQ-001 (프로젝트 열기) |
| `ReferencePanelView` | REQ-006 (참조 패널) |
| `TextSearchPanelView` | REQ-008 (전문 검색) |
| `DefinitionCandidatesView` | REQ-005 AC-2 (동명 정의 후보) |
| `EditSessionOverlayView` | REQ-004 AC-5 (편집 세션 끊김) |
| `ToolbarView` · `SidePanelView` | 셸 구성요소 |

**23:14 갱신 — 조립이 대부분 끝났다.** `PlaceholderPane` **0**, 위 표의 뷰는 전부 마운트됐다.
남은 미마운트는 셋:

| 미마운트 | 막힌 요구사항 |
|---|---|
| `IndexStatusChipView` | REQ-009 · REQ-002 AC-4 (인덱스 상태 칩) |
| `SymbolSearchModalView` | REQ-007 (심볼 퍼지 검색) |
| `ShellSplitter` | **REQ-011 AC-3 — 드래그 리사이즈 + 비율 재시작 복원** |

`ShellSplitter` 는 게이트 마운트 목록에도 없었고, 레포 전체에서 `DragGesture` 와 분할 비율
로직을 가진 파일이 그것 하나다. 즉 **지금 창은 영역 크기를 조절할 수 없다.**

이 값이 필요한 이유: 뷰가 컴파일되고 테스트를 통과해도 **아무도 인스턴스화하지 않으면
사용자에게 도달하지 않는다**. 그리고 그 상태에서도 게이트는 초록이다. 실제로 630여 테스트가
통과하는 동안 창은 회색 판 3장이었고, 그 사이 미연결 뷰는 5종에서 9종으로 **늘었다**.

**병목은 만드는 것이 아니라 꽂는 것이다.** 조립 지점(`MainWindowView`)은 프론트 시니어 소유다.

⚠ 마운트 카운트는 *꽂혔는지*만 본다. *제대로 그려지는지*는 아래가 본다.

### 이 지표의 맹점 (쓰기 전에 알아야 한다)
`Type(` 형태의 **생성자 호출만** 잡는다. 정적 멤버로만 쓰이는 타입은 실제로 쓰이는데도 0 으로
나온다 — 실측: `PanelTint`(`PanelTint.warning.dynamicColor` 로 2곳에서 사용) ·
`CodeNavigatorApplication`(`CodeNavigatorApplication.run()`). **0 을 미사용으로 읽기 전에
정적 멤버 사용을 확인한다.**

그리고 반대 방향의 맹점이 더 위험하다: **검사 목록이 손으로 관리되면 새 뷰는 기본적으로
검사에서 빠진다.** 실제로 `IndexStatusChipView` · `SymbolSearchModalView` · `ShellSplitter`
셋이 미마운트인데 목록에 없어 게이트가 통과했다. 목록은 **기본 포함**이어야 한다 —
`View/` 의 뷰 타입을 전부 열거해 마운트를 요구하고, 의도적 예외만 명시적 허용목록에 둔다.
(그 때 `PanelTint` 같은 정적 전용 타입은 허용목록에 넣되 *이유를 적는다*.)

### 이미 있는 렌더링 계기 (QA 정정 반영)
`GridRenderingTests` 는 **오프스크린 비트맵에 실제로 그리고 픽셀을 샘플링**한다 — 순수 함수
테스트가 아니다. 더블폭 문자·`startColumn`·커서 폭이 픽셀 수준 방어선을 갖는다(변이 실측 확인).
**화면 잠금과 무관하게 돈다.**
→ 그러므로 "렌더링을 재는 계기가 하나도 없다"는 틀렸다. **없는 것은 합성 층의 계기** —
어떤 뷰가 실제로 창에 꽂히는가. 마운트 카운트가 그 자리를 메운다.

## 2. 게이트 (리더가 직접 재실행 — 팀 주장이 아니라)

```bash
bash _workspace/gate.sh
```

포함: `swift build` · `swift test --no-parallel` · 실행 테스트 수 하한 · `.app` 조립 ·
번들 실행 검증 · 번들 검사기 자체 검사 · 민감정보 스캔.

**`--no-parallel` 인 이유**: 다섯 스위트가 각자 실제 Neovim 을 띄워, 병렬에서는 같은 코드가
부하에 따라 통과하기도 실패하기도 했다(5회 중 3회 실패 → 직렬 3회 전부 통과).

여기에 **뷰 조립 방어선**이 더해져야 한다(프론트 시니어 작업):
뷰 인스턴스화 테스트 + 조립 지점 고정. 단언 대상은 **"플레이스홀더가 아니다"** 여야 한다 —
"뷰가 만들어졌다"만 단언하면 플레이스홀더가 남아 있어도 통과한다.

## 5. 비기능 실측

### 이미 닫힌 것 (23:5x, backend-junior 실측 + 리더 확인)
| 항목 | 기준 | 실측 | 여유 |
|---|---|---|---|
| REQ-NF-001 전문 검색(리터럴, 전체 스캔) | ≤2000ms | **305ms** | 6.5배 |
| REQ-NF-001 전문 검색(정규식, 전체 스캔) | ≤2000ms | **250ms** | 8배 |
| REQ-NF-001 초기 인덱싱(5,000파일) | ≤10초 | 기존 스위트 통과 | — |
| REQ-NF-001 증분 갱신 | ≤500ms | 기존 스위트 통과 | — |
| REQ-NF-001 심볼 검색 | ≤100ms | 기존 스위트 통과 | — |
| REQ-NF-002 앱 번들 | ≤200MB | **11MB** | 18배 |

질의는 **레포 전체를 훑어야 하는 것**으로 골랐다. 흔한 단어는 상한 500건에 금방 닿아 일찍
멈추므로 최악을 재지 못한다 — 그건 따로 재서 상한이 실제로 작동하는지 확인했다.

### 아직 남은 것 — `.app` 의 실제 메모리
| 항목 | 기준 | 상태 |
|---|---|---|
| REQ-NF-002 · SC-8 유휴 메모리 | ≤150MB | 테스트 프로세스에선 **27.4MB**(인덱스 비용 19.1MB, 심볼 25,000). **`.app` 실측은 미완** |
| REQ-NF-003 기동 | ≤2초 | 실행부터 조작 가능까지 — `.app` 실측 필요 |

⚠ **테스트 프로세스의 숫자는 `.app` 의 숫자가 아니다.** SC-8 의 최종 인증은 실행 중인 앱에서 잰다.

### 측정에서 걸린 거짓 그린 둘 (같은 실수를 반복하지 않기 위해)
1. **측정 대상이 이미 해제돼 있었다.** 첫 측정값이 "인덱스 비용 0.3MB" 였는데, 25,000 심볼이
   그럴 리 없다. 원인은 마지막 사용 이후 **ARC 가 엔진을 먼저 해제**한 것 — 사라진 인덱스를
   재고 "메모리를 거의 안 쓴다"고 통과하고 있었다. `withExtendedLifetime` 으로 감싸니 20.1MB.
2. **같은 프로세스에서는 증가분이 0 으로 나온다.** 앞선 테스트가 잡아둔 페이지를 재사용하기
   때문이다(단독 20.1MB / 전체 스위트 안에서 0.0MB). 그래서 SC-8 은 게이트에서 **격리 실행**해
   출력 숫자로 판정한다.

→ 그리고 숫자를 믿기 전에 **측정기 자체를 검사**했다(50MB 를 실제로 할당·터치 → 관측 증가
50.0MB). **측정기가 죽어 있으면 150MB 예산 테스트는 무엇을 재든 영원히 통과한다.**

## 6. 증거로 인정하지 않는 것

- **"파일이 존재한다"** — 라우트 파일이 있고 등록도 됐는데 엔드포인트가 TODO 였던 사례가 있다.
- **"테스트가 전부 초록"** — 존재하는 테스트의 그린일 뿐이다. 뷰 테스트 0건인 상태에서도 630건이 초록이었다.
- **매트릭스의 `테스트 상태` PASS** — "나열된 테스트가 통과한다"는 뜻이지 화면 성립이 아니다.
- **`--self-check` 통과** — `CodeNavigatorMain.swift` 에서 `run()` **이전에 return** 한다. 창·뷰 생성을 실행하지 않는다.
- **팀의 자가 라이브 E2E·디자인 충실도 PASS** — 이 둘은 리더 인증 단계다. 팀이 돌렸으면 "팀 자가검증(리더 인증 대기)"로만 표기한다.
- **빈 명령 출력** — 그 명령이 잡을 수 있는지부터 확인한다. 리더가 `ioreg` 빈 결과를 "잠금 해제"로 오독했고,
  스크린샷 파일 크기를 "찍힘"의 증거로 삼았다(내용은 배경화면이었다).
