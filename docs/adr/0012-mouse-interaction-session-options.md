# 0012. 마우스 상호작용 — `mouse`를 세션에서 보장한다

- 상태: 채택
- 영역: 백엔드 (backend-senior)
- 날짜: 2026-09-01

## 맥락

REQ-017은 클릭으로 커서 이동, 드래그로 비주얼 선택, 선택의 화면 표시, 그 선택에 Vim 명령이
먹을 것을 요구한다. `nvim_input_mouse`를 부르는 경로와 `EditorMouseEvent` 계약은 REQ-010에서
이미 만들어져 있었다. 그러므로 물음은 "무엇을 새로 만드는가"가 아니라 **"지금 무엇이 빠져
있는가"**였고, 그것은 짐작이 아니라 측정으로만 답할 수 있었다.

## 결정

**세션 기동 시 `mouse=a`를 건다.** 사용자 설정 파일은 수정하지 않는다(INV-7) — `showtabline=0`과
같은 급의, 이 세션에만 적용되는 상호작용 계약이다.

계약은 **바꾸지 않는다.** `EditorMouseEvent`·`EditorGridSnapshot`·`EditorTextStyle` 그대로다.

## 실측 (spike, 2026-09-01 — Neovim 0.12.5, 트리 `c7a6bf7`)

| 잰 것 | 결과 |
|---|---|
| `&mouse` 기본값 | **`nvi`** — 비어 있지 않다 |
| `&mousemodel` / `&selection` | `popup_setpos` / `inclusive` |
| 클릭 → 커서 | 셀 행 2 클릭 → 버퍼 3줄. 이동한다 |
| 드래그 → 선택 | `mode()='v'`, 선택 3줄 |
| 선택이 화면에 오는가 | **온다.** 배경이 칠해진 셀 60 → 115 |
| 뷰의 배선 | `mouseDown`→press, `mouseDragged`→drag, `mouseUp`→release 전부 연결됨 |

### `mouse` 옵션 의존성 — 이 측정이 결정을 만들었다

| `&mouse` | 클릭 후 커서 줄 | `mode()` | 선택 줄 수 |
|---|---|---|---|
| `nvi` (기본) | 3 | `v` | 3 |
| `''` (사용자가 껐을 때) | **3** | `n` | **1** |
| `a` | 3 | `v` | 3 |

> **`mouse=''`에서 클릭은 살아 있고 드래그만 죽는다.**

이것이 이 ADR의 이유 전부다. "클릭하면 커서가 간다"만 확인하는 테스트는 **초록인 채로 통과하고,
드래그 선택은 조용히 죽어 있다.** 지난 빌드의 `BUILD_COMPLETE`가 기록한 "테스트가 초록인데
기능이 죽어 있다" 여덟 건과 같은 모양이며, 하나의 검사가 두 능력을 대표한다고 가정할 때 생긴다.

### 리더의 사전 가설과 실측의 차이 (기록으로 남긴다)

착수 지시는 "`set mouse=a`가 세션에 안 걸려 있을 가능성이 커 보인다"는 정적 추측을 담고 있었고,
지시 자체가 그것을 근거로 쓰지 말고 재라고 명시했다. **재 보니 절반만 맞았다** — 옵션은 걸려
있고(`nvi`) 기본값으로도 세 AC가 이미 동작한다. 맞은 절반은 "옵션이 이 기능의 급소"라는 것이고,
그 급소는 기본값이 아니라 **사용자가 껐을 때** 드러난다.

## 고려한 대안

1. **아무것도 하지 않는다** — 기본값이 `nvi`이므로 대부분의 사용자에게 REQ-017은 이미 참이다.
2. **`mouse` 값을 읽어 비어 있을 때만 켠다** — 사용자 의사를 최대한 존중.
3. **무조건 `mouse=a` (채택)**

## 트레이드오프

- **1(아무것도 안 함)**은 코드가 0이지만, `set mouse=`를 쓰는 사용자에게 요구가 거짓이 된다.
  그 사용자는 드문 부류가 아니다 — 터미널에서 마우스를 끄는 것은 Vim 사용자의 흔한 설정이고,
  그들이 바로 이 앱의 대상이다. 게다가 실패가 **부분적**이라 "클릭은 되는데 드래그만 안 되네"로
  나타난다. 진단이 가장 어려운 실패 모양이다.
- **2(비어 있을 때만 켠다)**는 존중처럼 보이지만 결과가 **비결정적**이다. 같은 앱이 어떤
  사용자에겐 드래그가 되고 어떤 사용자에겐 안 된다. REQ-017은 조건부 요구가 아니다. 그리고
  이 존중은 REQ-015 AC-6의 존중과 성격이 다르다 — **키는 손버릇이라 사용자 것이 이겨야 하지만,
  마우스 활성화는 손버릇이 아니라 이 창이 마우스를 받는 창인지의 문제다.** 사용자가 터미널
  Vim에서 마우스를 끈 것은 터미널에 대한 판단이지, 마우스로 조작하는 GUI 앱에 대한 판단이 아니다.
- **3(무조건)**은 모든 사용자에게 같은 동작을 준다. 대가는 사용자 옵션 하나를 세션 안에서
  덮는 것이고, 그 덮음은 프로세스 수명을 넘지 않으며 사용자 파일에 남지 않는다.

- **테스트 용이성**: `mouse=''`를 만들어 놓고 드래그를 단언하는 회귀 테스트가 가능하다.
  위 표가 그대로 테스트가 된다.
- **단순성**: 한 줄이다. 분기가 없다.
- **되돌림**: 세션 옵션이므로 지우면 끝이다.

## 채택 이유 (이 프로젝트 기준)

REQ-017의 네 AC 중 셋이 이미 동작한다는 것을 실측했다. 이 ADR이 방어하는 것은 **아직 일어나지
않은 실패**다 — 우리 테스트 머신의 기본값에서는 보이지 않고, 마우스를 끈 사용자에게서만,
그것도 절반만 나타나는 실패.

기본값이 우리를 살려 주고 있다는 것과 요구가 충족됐다는 것은 다른 말이다. 기본값은 사용자가
바꿀 수 있다.

## 결과 (구현 시 반드시 지킬 것)

- `mouse=a`는 **설정 로드 이후**에 건다. 사용자 `init.lua`의 `set mouse=`가 나중에 실행되면
  우리 설정이 덮인다(ADR-0006: 설정은 `nvim_ui_attach` 시점에 실행된다).
- 회귀 테스트는 `mouse=''`를 명시적으로 만든 뒤 드래그를 단언한다. **기본값 상태만 확인하는
  테스트는 이 결정이 지키려는 것을 하나도 지키지 않는다.**
- 클릭과 드래그를 **각각** 단언한다. 하나가 다른 하나를 대표하지 않는다는 것이 실측 결과다.
- 이 ADR은 **엔진 경계까지만** 주장한다. 실제 앱에서 마우스가 화면에 어떻게 도달하는지
  (픽셀→셀 변환·포커스·입력 차단)는 프론트엔드 영역이며 라이브로 측정돼야 한다.
