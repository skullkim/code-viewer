# ADR-0117 — 실행 설정을 소스에서 알아내고, 디버그 부착은 명령마다 다르게 한다

- 상태: 채택
- 날짜: 2026-09-08
- 관련: [ADR-0116](0116-running-through-the-bundled-terminal.md) (실행·터미널), REQ-018

## 맥락

사용자 요구: "실행과 디버깅에 필요한 세팅이 소스를 분석해서 자동으로 등록되게 할 수 없나?"

착수 전에 실측을 하나 했고, 거기서 v0.5.0 의 결함이 드러났다. `JAVA_TOOL_OPTIONS` 는
**모든 자식 JVM 이 물려받는다.** `./gradlew bootRun` 에 걸면 Gradle **런처** JVM 이 먼저
그것을 집어 포트를 잡고 `suspend=y` 로 멈춘다 — 앱은 뜨지도 않는다.

```
$ JAVA_TOOL_OPTIONS="-agentlib:jdwp=...suspend=y,address=127.0.0.1:5099" ./gradlew --version
Listening for transport dt_socket at address: 5099      ← 런처가 멈췄다
$ lsof -nP -iTCP:5099
java  72972 ... 127.0.0.1:5099 (LISTEN)                 ← 런처가 포트를 잡았다
```

즉 v0.5.0 의 디버그 실행은 Gradle/Maven 프로젝트에서 엉뚱한 JVM 에 붙는다. 자동 감지는
"무엇을 띄우는지" 뿐 아니라 "어떻게 붙는지" 까지 정해야 의미가 있다.

## 결정

### 1. 부착 방식을 설정이 들고 다닌다

`DebugLaunchStrategy` 를 `RunConfiguration` 에 넣는다. 매번 명령 문자열을 다시 뜯어
추측하면, 사용자가 명령을 조금 고칠 때마다 붙는 방식이 소리 없이 바뀐다.

| 전략 | 어떻게 | 왜 |
|---|---|---|
| `javaToolOptions` | 환경변수 | `java` 를 직접 부르는 명령. JVM 이 표준으로 읽는다 |
| `gradleDebugJvm` | 명령에 `--debug-jvm` | Gradle 이 **자기가 포크한** JVM 에만 붙인다. 런처는 안 건드린다 |
| `mavenJvmArguments` | `-Dspring-boot.run.jvmArguments` | 플러그인이 포크한 JVM 에 넘긴다 |
| `unsupported` | 안 붙는다 | Node·Python·Go. 버튼을 막는다 |

### 2. 실제로 열릴 포트를 함께 답한다

실측(Gradle 8.14.5): `--debug-jvm` 에 `-Dorg.gradle.debug.port=6001` 을 같이 줘도 앱 JVM 은
`address=5005` 로 떴다. 그 옵션은 `org.gradle.debug`(Gradle **자신**을 디버깅) 쪽 것이지
태스크 쪽이 아니다.

그래서 `debugLaunch(port:)` 는 명령·환경뿐 아니라 **실제로 열릴 포트**를 함께 돌려준다.
요청값을 그대로 들고 붙으러 가면 6001 을 두드리고 앱은 5005 에서 기다린다 — 화면에는
"붙지 못했습니다" 만 뜬다. 먹지 않는 `-D` 옵션은 아예 붙이지 않는다: 있지도 않은 조절
수단이 있는 것처럼 보이기 때문이다.

### 3. 감지는 순수 함수, 훑기는 따로

`RunConfigurationDetector` 는 파일 목록과 "이 경로의 내용을 다오" 만 받는다. 디스크를 직접
읽으면 규칙 하나를 시험하는 데 매번 진짜 프로젝트를 만들어야 하고, 그런 테스트는 느리고
흔들린다. `ProjectRunScanner` 가 디스크만 담당한다.

빌드 도구가 우선이고, 하나도 못 찾았을 때만 `main` 클래스를 뒤진다 — Gradle 프로젝트 안에는
`main` 이 여럿이라 같이 넣으면 목록이 지저분해진다. 매니페스트는 3단계까지만 내려간다
(모노레포의 `backend/`·`apps/api/` 까지). 소스 파일에는 그 한도를 걸지 않는다 —
`src/main/java/com/example/App.java` 는 평범한 자바 경로다.

### 4. 환경변수는 자동으로 채우지 않는다

`.env` 를 읽어 넣으면 비밀값이 앱 설정 파일로 복사된다. 게다가 대부분의 프레임워크
(dotenv·Spring)가 그 파일을 이미 스스로 읽는다. 자동으로 정하는 것은 **명령·작업 폴더·
디버그 전략** 셋뿐이다.

### 5. 감지 결과는 저장하지 않는다

목록에 바로 보이되(`· 감지됨` 표시), 사용자가 고쳐 저장할 때 비로소 설정이 된다. 이름이
같으면 저장한 쪽이 이긴다. 그래야 "사용자가 고친 것을 다음 스캔이 덮어썼다" 가 원천적으로
없다 — 그건 되돌릴 수 없는 손실이다.

## 대안

| 안 | 왜 안 골랐나 |
|---|---|
| 명령 문자열을 볼 때마다 전략을 추측 | 사용자가 명령을 고치면 붙는 방식이 소리 없이 바뀐다 |
| 감지 결과를 설정에 바로 저장 | 다음 스캔이 사용자의 수정을 덮어쓴다. 되돌릴 수 없다 |
| `.env` 를 읽어 환경변수까지 채움 | 비밀값이 설정 파일로 복사되고, 프레임워크가 이미 읽는다 |
| Gradle 에도 `JAVA_TOOL_OPTIONS` | 런처가 가로챈다 — 이 ADR 이 존재하는 이유 |
| 요청한 포트를 그대로 믿기 | Gradle 은 5005 로 고정한다. 엉뚱한 포트로 붙으러 간다 |

## 결과

- 프로젝트를 열면 실행 설정이 저절로 목록에 오른다. 실측한 네 저장소에서 모두 맞았다.
- Gradle/Maven 프로젝트의 디버그 실행이 **처음으로 실제 동작한다.**
- 디버그로 못 띄우는 명령은 버튼이 회색이고, 이유를 말한다.
- 훑기는 2,700 파일 저장소에서 0.05초다. `node_modules` 등에는 들어가지 않는다.

## 알려진 한계

- **`~/Documents` 아래 프로젝트가 조용히 안 열린다** — macOS 의 파일 접근 권한(TCC) 문제다.
  같은 설정으로 `/private/tmp` 는 열리고, 터미널에서 띄우면(권한 상속) `~/Documents` 도
  열린다. 앱이 그 사실을 화면에 말하지 않는 것은 별개 결함으로 남아 있다.
- Node 는 V8 인스펙터라 지금 디버거로는 못 붙는다. 붙이려면 별도 프로토콜이 필요하다.
