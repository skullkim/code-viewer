# 0004. 파일 열거·전문 검색 = 네이티브 Swift (ripgrep 비의존)

- 상태: 채택
- 날짜: 2026-08-29
- 결정자: backend-senior

## 맥락
웹앱판은 파일 열거·전문 검색·참조 검색을 전부 ripgrep 바이너리에 위임했다(ADR-0004 웹앱판).
`.gitignore` 존중을 공짜로 얻고, 인덱싱과 검색이 같은 스캔셋을 공유해 REQ 간 일관성이 확보되는
좋은 결정이었다. 네이티브 앱에서도 같은 선택을 할 수 있지만, 이번엔 **바이너리를 앱 번들에
넣고 서브프로세스로 띄우는 비용**이 따라온다.

이 앱은 이미 외부 의존이 하나 있다(Neovim, REQ-NF-005). 두 번째를 늘릴지가 쟁점이었다.

## 결정
**ripgrep을 쓰지 않는다. 파일 열거·전문 검색·참조 검색을 네이티브 Swift로 구현한다.**
`.gitignore` 매칭도 자체 구현한다.

## 실측 (spike, 2026-08-29 — 5,000파일 / 15MB 합성 코퍼스, release 빌드)
| 항목 | 네이티브 Swift | ripgrep 15.0.0 |
|---|---|---|
| 파일 열거 | 15–27ms | ~10ms |
| 전 파일 읽기(병렬) | 36ms | — |
| 리터럴 검색 (`Data` 바이트 탐색) | 55ms | ~40ms |
| 리터럴 검색 (`String.range(of:)`) | 253ms | — |
| 정규식 검색 (`NSRegularExpression`) | 33ms | — |
| 피크 RSS | 30MB (전문을 String으로 보유한 상태) | 6MB (스트리밍) |

목표는 인덱싱 ≤10초·전문 검색 ≤2초다. 네이티브 경로의 열거+읽기+검색 합이 **0.5초 미만**으로,
목표 대비 20배 이상의 여유가 있다. ripgrep이 절대 속도로는 빠르지만, **그 차이가 사는 요구사항이 없다.**

시스템 `rg` 실측 결과: PATH에 실제 바이너리가 **없다**(대화 셸의 `rg`는 하네스가 주입한 함수 —
직전 프로젝트와 동일한 거짓 양성 패턴). 즉 ripgrep을 쓰려면 반드시 번들링해야 하고,
그러려면 arm64 바이너리(압축 1.68MB / 전개 4.3MB)를 받아 검증하고 앱 번들에 넣는 빌드 단계가 필요하다.

## 고려한 대안
1. **ripgrep 바이너리 번들링** — `.gitignore` 의미론을 공짜로 얻고 검색이 빠르다. 대신
   (a) 다운로드·무결성 검증·번들 배치라는 빌드 단계, (b) 미서명 앱이 번들 바이너리를 spawn하는
   Gatekeeper 리스크, (c) 아키텍처별 바이너리 관리, (d) 검색마다 프로세스 spawn.
   무엇보다 **정규식 검증이 취약해진다**: 웹앱판은 Rust regex가 거부하는 패턴(룩비하인드·역참조)을
   `rg`의 stderr에서 `'regex parse error'` 문자열을 찾아 판별했다. 영문 에러 메시지 문자열에
   의존하는 방어선이다. 기각.
2. **`FileManager` + `NSRegularExpression` 네이티브 (채택)** — 외부 바이너리 0, 서브프로세스 0.
   정규식 유효성은 `NSRegularExpression` 생성 실패로 **직접·확실하게** 판정된다(REQ-008 AC-2가
   문자열 매칭 없이 성립). 비용은 `.gitignore` 매처를 직접 구현하는 것 하나다.
3. **`.gitignore` 무시하고 기본 제외 목록만** — 가장 싸지만 REQ-001 AC-4 위반. 기각.

## 트레이드오프
- 얻는 것: 외부 의존 제거(설치 편차·PATH·격리 속성 문제 소멸), 정규식 에러 판정이 견고해짐,
  전 과정이 인프로세스라 테스트가 결정적이고 빠름.
- 잃는 것: `.gitignore` 의미론(부정 패턴 `!`, 디렉토리 전용 `/`, `**`, 앵커링, 중첩 파일)을
  직접 구현하고 직접 테스트해야 한다. 이것이 이 결정의 **유일한 실질 리스크**이며,
  잘 정의된 순수 함수라 테스트로 방어 가능하다고 판단했다.
- 되돌리기: 스캔·검색이 프로토콜 뒤에 있으므로 ripgrep 구현으로 갈아끼우는 것은 국소 변경이다.

## 결과
- 리터럴 검색은 `String.range(of:)`를 쓰지 않는다(유니코드 grapheme 비교 때문에 4.6배 느림).
  UTF-8 바이트 탐색으로 찾고, 오프셋을 UTF-16으로 환산한다(ADR-0007).
- 제외 규칙은 스캐너·전문 검색·참조 검색이 **하나의 모듈을 공유**한다. 웹앱판이 공유 인자 배열로
  얻었던 REQ 간 일관성을, 여기서는 공유 타입으로 얻는다.
- 심링크는 따라가지 않는다(심링크 루프 방어, REQ-NF-004). 바이너리 파일은 열거에는 포함하되
  내용 읽기 단계에서 NUL 바이트 스니핑으로 건너뛴다.
