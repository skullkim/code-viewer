# ADR-0102: 키 라우팅 — 앱은 ⌘ 조합만 가져가고, 표기법 생성까지만 소유한다

- 상태: 채택
- 영역: 프론트엔드 (frontend-senior)
- 날짜: 2026-08-29

## 맥락

REQ-011 AC-2는 앱 단축키가 **Neovim 입력과 충돌하지 않을 것**을 요구한다. Vim은 `⌃O`(점프 뒤로)·
`⌃R`(redo)·`⌃V`(비주얼 블록)·`⌃W`(창 이동) 같은 Control 코드를 핵심 조작에 쓰고, 일반 문자는
전부 편집 입력이다. 동시에 REQ-010은 Vim ↔ 표준 두 해석 계층을 요구한다.

## 결정

**두 겹으로 나눈다.**

1. **가로채기 규칙**: 앱은 **⌘를 포함한 조합만** 가져간다. 나머지(⌃ 단독, ⌥ 단독, 일반 키)는
   가공 없이 Neovim으로 간다. 구현은 AppKit 기본 동작에 맡긴다 — 그리드 뷰가
   `performKeyEquivalent`에서 `false`를 반환하면 메뉴가 ⌘ 조합을 claim 하고 나머지는 `keyDown`으로 떨어진다.
   전역 `NSEvent` 모니터를 쓰지 않는다.
2. **번역 책임**: 앱은 `NSEvent` → **Neovim 키 표기법 문자열** 생성까지만 한다. 입력 모드에 관계없이
   **항상 같은 문자열**을 만든다. 모드별 해석(표준 모드의 맥 관례 매핑)은 `EditorSession`이 한다.

## 고려한 대안

- **A. 전역 `NSEvent.addLocalMonitorForEvents`로 모든 키를 잡아 앱이 분기** — 단축키 테이블을 앱이 소유.
- **B. 앱이 입력 모드까지 해석**해 표준 모드에서 ⌘Z→undo, 화살표→커서 이동 등을 앱이 직접 매핑.
- **C. 메뉴 키equivalent + `performKeyEquivalent: false` + 표기법 생성만 (채택)**

## 트레이드오프

- **A**는 단축키를 한곳에 모아 읽기 좋지만, 모니터가 이벤트를 먼저 보므로 **무엇을 통과시킬지 매번
  판단**해야 한다. 판단이 하나라도 틀리면 Vim 키가 조용히 먹힌다. 게다가 메뉴 항목의 활성/비활성
  상태(REQ-010 AC-5의 편집 메뉴 분기)와 단축키 처리가 **두 곳으로 갈린다**.
- **B**는 표준 모드를 앱이 온전히 통제해 즉각적이지만, 맥 관례 편집은 **Neovim의 내부 상태와 결합**돼
  있다(삽입 모드 유지, 선택 모델, undo 경계). 앱이 그걸 하려면 nvim 상태를 추적해야 하고 그것이
  곧 상태 분기다 — REQ-010이 "두 에디터를 병존시키지 않는다"로 금지한 바로 그 함정이다.
- **C**는 경계가 **문자열 하나**다. 앱 쪽 테스트는 "NSEvent → 표기법"과 "⌘ 조합 → 앱 커맨드"이고,
  엔진 쪽 테스트는 "표기법 + 입력 모드 → nvim 동작"이다. 서로를 몰라도 각자 검증된다.

- **테스트 용이성**: C의 표기법 변환은 순수 함수라 이벤트 없이 단위 테스트된다.
- **위임 적합성**: 라우팅 규칙이 규칙 하나("⌘면 앱")로 압축돼 주니어가 새 메뉴 항목을 추가해도
  Vim 입력을 깨뜨릴 수 없다.
- **되돌림**: 규칙을 바꾸려면 뷰 한 곳(`performKeyEquivalent`)만 손대면 된다.

## 채택 이유

REQ-011 AC-2의 "충돌하지 않는다"를 **매번의 판단이 아니라 구조**로 만든다. 실측으로 확인했다 —
`.app` 번들에서 합성 이벤트를 실제 디스패치 경로(`NSApp.sendEvent`)에 태운 결과:

- ⌘O·⌘P·⇧⌘F·⌘S·⌃⌘V·⌃⌘R → **전부 메뉴가 claim**(뷰는 못 봄)
- ⌃O·⌃R·⌃V·⌃W·`i`·`h`·`:`·Esc·←·⇧↓ → **전부 뷰에 도달**, 표기법 `<C-o>`·`<C-r>`·`<C-v>`·`<C-w>`·
  `i`·`h`·`:`·`<Esc>`·`<Left>`·`<S-Down>` 생성

추가 코드 없이 AppKit 기본 동작만으로 규칙이 성립한다.

## 이 spike가 잡은 함정 2건 (구현 시 재발 금지)

1. **메뉴 키equivalent에 대문자 + Shift 마스크를 동시에 주면 매칭이 실패한다.**
   `keyEquivalent: "F"` + `[.shift, .command]`로 만든 ⇧⌘F가 메뉴에 안 걸리고 **Neovim으로 새어 나갔다**.
   대문자가 이미 Shift를 함의해 이중 계산된다. 소문자 `"f"` + `[.shift, .command]`가 정답.
2. **`charactersIgnoringModifiers`로 표기법을 만들면 `:`가 `;`로 나간다.** ⇧;가 콜론인데 수식키를
   무시한 문자는 세미콜론이라 **Vim 명령 모드에 진입할 수 없다.** 수식키 없는 인쇄 문자는
   `characters`를, ⌃/⌥/⌘ 조합일 때만 `charactersIgnoringModifiers`를 쓴다(그 조합들은 미변형 키
   이름으로 불리기 때문).

둘 다 회귀 테스트로 고정한다.
