# 0111. 탭 목록이 두 벌인 것을 단일화하지 않고 발산 경로를 닫는다

- **상태**: 채택 (2026-08-31)
- **관련**: REQ-012, [0107 탭 단위 상태](0107-tab-scoped-state.md), [0106 프로젝트 워크스페이스](0106-project-workspace.md)

## 맥락

열린 프로젝트 목록이 **두 곳**에 있다.

| 장부 | 소유 | 무엇을 아는가 |
|---|---|---|
| `ProjectWorkspaceEngine.tabs()` | 엔진 | 세션이 살아 있는 프로젝트 |
| `AppModel.tabs` (`ProjectTabSet`) | 앱 | 화면에 그려지는 탭 |

**앱은 `tabs()` 를 한 번도 부르지 않는다.** 둘을 맞춰 주는 코드도 없다. 각자 갱신된다.

그래서 물어야 할 것은 *"지금 같은가"* 가 아니라 **"갈라질 수 있는가"** 였다. 세션 조회가
`nil` 을 주는 탭을 만들어 재니 두 경로가 갈라졌다:

```
복원      엔진 2개 · 앱 1개 · 못 열었다고 보고 0개   → 한 탭이 조용히 사라진다
열기 실패  앱은 오류 표시·탭 없음 · 엔진에 탭 잔존   → 고아 탭이 남는다
```

두 자리 다 같은 모양이었다:

```swift
guard let session = await workspace.session(for: tab.id) else { continue }
```

**"못 얻었으면 건너뛴다." 그리고 건너뛴 것이 어디에도 기록되지 않는다.**

### 왜 조용한 것이 나쁜가

사라진 탭은 사라지지 않는다. **세션을 쥐고 배경에서 인덱싱한다.** 화면에 없으니 사용자는
그것을 **보지도 닫지도 못한다** — 리소스를 쓰는데 조작 표면이 없다. 앱이 왜 느린지 알 방법이
없다. 그냥 안 보이는 것보다 나쁘다.

## 결정

**두 장부를 단일화하지 않는다. 대신 발산 경로를 닫는다.**

세션을 얻지 못한 탭은 **엔진에서 닫고, 못 열었다고 말한다**(W-12 시트):

- 복원: `continue` → 엔진 탭을 닫고 `MissingTab` 으로 보고
- 열기 실패: 오류만 세우고 반환 → **엔진이 만든 탭을 되돌린 뒤** 오류

규칙 한 줄로: **되돌리고 말한다.**

## 고려한 대안

### A. 앱이 `tabs()` 를 단일 소스로 쓴다 (기각 — 지금은)
가장 옳은 구조다. 장부가 하나면 갈라질 수 없다.

기각 이유는 옳지 않아서가 아니라 **시점** 이다. 앱의 `ProjectTabState` 는 탭마다
`FileTreeModel`·인덱스 상태·`RenderViewSelection` 을 들고 있어(0107), 이걸 엔진 목록에서
파생시키려면 탭 단위 상태의 수명 관리를 통째로 다시 짜야 한다. **인증 직전에 할 일이 아니다.**

→ 인증 후 별도 ADR 로 다룬다.

### B. 두 장부를 주기적으로 대조·동기화 (기각)
동기화는 **갈라짐을 전제** 하고, 갈라진 창(window) 동안의 동작을 정의하지 않는다.
"언젠가 맞춰진다"는 조용한 결함을 늦게 발견되는 결함으로 바꿀 뿐이다.

### C. `session(for:)` 실패를 무시하고 세션 없이 탭을 만든다 (기각)
화면에는 탭이 보이는데 그 안의 트리·검색·인덱스가 전부 죽어 있다. **보이지 않는 탭보다
나쁜 것은 동작하지 않는데 동작하는 것처럼 보이는 탭이다.**

## 트레이드오프

- **테스트 용이성** ★ — 발산을 *만들 수 있게* 하는 것이 핵심이었다. `FakeWorkspace` 에
  `sessionlessRoots` 훅을 더해 "엔진은 탭을 들고 있는데 세션 조회만 nil" 상태를 구성한다.
  **틈이 닫혔는지 재려면 먼저 틈을 만들 수 있어야 한다.**
- **단순성** ★ — 두 자리, 각각 세 줄. 구조 변경 0.
- **되돌림** ★ — A 로 가는 길을 막지 않는다. 오히려 A 를 할 때 이 테스트가 회귀 방어선이 된다.
- **변경 가능성** ▲ — 장부는 여전히 둘이다. 새 경로가 생기면 그 경로도 같은 규칙을 지켜야 하고,
  **지키지 않아도 컴파일은 된다.** 이것이 A 를 미룬 값이다.

## 도달 가능성에 기대지 않는다

현재 `ProjectWorkspaceEngine` 은 `sessions[id]` 와 `orderedTabs` 를 같이 갱신하므로, 진짜
엔진에서 이 상태가 **지금은** 도달 불가능할 수 있다. 확인하지 않았고, **근거로 쓰지 않는다.**

앱이 두 장부를 따로 드는 **구조 자체가** 그 틈을 허용한다. 도달 불가에 기대는 것이
*"우연히 동작한다"* 의 정의다 — 같은 날 `⌃[` 가 두벌식이 문장부호를 안 바꾼다는 우연 하나로
두 번 "여긴 멀쩡하다"로 읽혔다(0110 인접, D-19).

## `tabs()` 는 죽은 코드가 아니다

앱이 안 부르는 것은 사실이다. 그러나 **`tabs()` 가 없으면 "두 장부가 갈라졌다"를 잴 수 없다** —
엔진의 장부를 밖에서 읽을 수 있어야 앱의 장부와 대조가 된다.

**검증 표면이며, 이 ADR 의 테스트가 그것을 오라클로 쓴다.** 은퇴 후보 목록에 올리지 말 것.

## 결과

`TabListSingleSourceTests` 2건. 단언은 **두 성질로 나눠** 적는다 — 한 식으로 묶었더니 고친
뒤에도 빨간불이었다(나쁜 탭을 닫으면 엔진 수가 주는 것이 정상인데, 묶은 식은 그것을 결함으로
읽었다):

```
① 두 장부가 같다        앱 == 엔진        (화면에 없는데 엔진이 든 탭이 없다)
② 요청한 것이 다 설명된다  앱 + 보고 == 요청  (조용히 빠진 것이 없다)
```

방어선 2종을 각각 변이로 실측했다 — 엔진 탭을 안 닫으면 2건 빨강, 못 열었다고 보고 안 하면
2건 빨강.
