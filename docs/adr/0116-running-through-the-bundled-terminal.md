# ADR-0116 — 실행과 터미널을 번들된 Neovim 위에 세운다

- 상태: 채택
- 날짜: 2026-09-07
- 관련: [ADR-0114](0114-bundling-neovim.md) (Neovim 번들), REQ-018

## 맥락

사용자 요구는 세 가지였다 — 서버를 앱 안에서 띄울 것, 그 실행에 환경변수를 넣을 것,
디버그 실행이면 디버거가 알아서 붙을 것. IntelliJ 의 Run/Debug 와 같은 것을 원한다.

앱 안에서 프로세스를 돌려 그 출력을 보여 주려면 터미널 에뮬레이터가 필요하다. 서버 로그는
색을 쓰고, 진행 표시줄은 커서를 움직이며, 스프링 배너는 창 폭에 맞춰 다시 그려진다.

## 결정

### 1. 터미널은 번들된 Neovim 의 `:terminal` 이다

PTY 와 VT100 파서를 직접 쓰지 않는다. 이미 Neovim 을 번들하고 있고(ADR-0114), 그 `:terminal`
은 libvterm 기반의 완전한 터미널이다 — 색·커서 모양·스크롤백·크기 변경까지 다 된다. 직접
쓰면 그 하나하나가 우리 결함이 된다. UI 프로토콜도 이미 다루므로 그리드 렌더러·키 입력이
그대로 재사용된다.

**편집기와는 다른 프로세스다.** 같은 인스턴스를 쓰면 터미널 버퍼가 편집기 자리를 차지하고
탭 전환이 서로를 밀어낸다. 터미널 쪽은 `--clean` 으로 띄운다 — 편집기는 INV-4 때문에 사용자
설정을 읽지만, 터미널에서 사용자 플러그인이 키를 가로채면 셸에 글자가 안 들어가고 그 증상은
"터미널이 고장났다" 로 보인다.

### 2. 디버그 실행은 명령을 고쳐 쓰지 않고 `JAVA_TOOL_OPTIONS` 로 붙인다

`-agentlib:jdwp=…` 를 명령 어디에 끼울지는 실행 방식마다 다르다 — `java` 직접 실행,
`./gradlew bootRun`, `mvn spring-boot:run` 이 전부 다르고, 우리가 명령을 파싱해 맞추면
사용자의 명령 하나하나가 우리 파서의 시험이 된다. 대신 JVM 이 표준으로 읽는 환경변수에
넣는다. 사용자가 적은 환경변수와 합칠 때는 **덮어쓰지 않고 이어 붙인다**.

### 3. 붙은 다음 반드시 재개한다

`suspend=y` 로 띄운다 — 시작 코드에 건 브레이크포인트를 놓치지 않기 위해서다. 그러면 JVM 은
한 줄도 실행하지 않은 채 우리를 기다리므로, 붙은 직후 풀어 주지 않으면 **서버가 영영 안
뜬다**. 사용자에게는 "디버그 실행을 눌렀는데 아무 일도 없다" 로만 보인다.

### 4. 레이아웃 전의 크기 보고를 pty 로 넘기지 않는다

그리드 뷰는 첫 레이아웃 패스에서 1×1 을 보고한다. 그 값이 pty 로 가면 libvterm 이 화면을
한 칸으로 줄이면서 **이미 찍힌 줄을 잘라 버리고**, 곧이어 진짜 크기가 와도 잘린 글자는
돌아오지 않는다. 실측: 서버 기동 로그가 12글자만 남았다.

편집기에서는 같은 보고가 눈에 띄지 않는다 — 버퍼가 원본을 들고 있어 다시 그리면 되기
때문이다. 터미널의 스크롤백에는 그 사본이 없다. 그래서 거르는 자리는 터미널 쪽이다.

## 대안

| 안 | 왜 안 골랐나 |
|---|---|
| PTY + VT100 파서 직접 구현 | 색·커서·스크롤백·리사이즈가 전부 우리 결함이 된다. 번들된 libvterm 이 이미 한다 |
| `Process` 로 돌리고 stdout 만 붙이기 | 진행 표시줄·색·창 폭 반응이 깨진다. 서버 로그는 대부분 그걸 쓴다 |
| 편집기 nvim 안에 터미널 버퍼 열기 | 터미널이 편집기 자리를 먹고, 탭 전환이 서로를 밀어낸다 |
| 명령 문자열에 `-agentlib` 끼워 넣기 | 실행 방식마다 자리가 달라 우리가 명령 파서를 갖게 된다 |
| `suspend=n` 으로 띄우기 | 재개는 필요 없어지지만 시작 코드의 브레이크포인트를 놓친다. 그게 디버그 실행의 이유다 |

## 결과

- 실행·디버그 실행·정지·터미널·실행 설정이 메뉴와 패널 양쪽에 있다.
- 환경변수는 표로 편집하고 설정에 저장된다.
- 번들 검증(`scripts/verify-bundle.sh`)이 실행·디버거 **배선**까지 확인한다 — 조립 한 줄이
  빠져도 창은 멀쩡히 그려지고 테스트도 통과하기 때문이다.
- 라이브 테스트(`RunAndDebugLiveTests`)가 진짜 JVM 으로 설정 → 터미널 → 환경변수 →
  자동 부착 → 브레이크포인트를 한 번에 확인한다. 자바가 없는 기계에서는 통과가 아니라
  **건너뜀**으로 표시된다.
